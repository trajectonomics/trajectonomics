# A What-if session is transient Overrides that the server reads through `traj`

A person asks "what if I stop the gym, or earn 10% more?" without changing the plan, sees the answer, and then keeps it as a new plan, applies it to the plan it came from, or drops it. The answer comes from `traj`, as every figure does ([ADR 0002](0002-the-cli-is-the-only-source-of-figures.md)). The CLI applies a what-if transiently with its Overrides ([cli ADR 0056](../../../cli/docs/adr/0056-a-what-if-takes-a-list-item-out-and-reads-its-amounts-in-major-units.md)), so the page holds the changes and asks for the reads.

## Decision

- **The session is in the tab.** A What-if session belongs to one plan. It holds that plan's name, the content hash the page read when the session began, the Sets (`path` and the JSON value that replaces it) and the Removals (the item ids switched off). It lives in `src/client/what-if-state.svelte.ts` and the session module in `src/lib/what-if/`. Nothing is stored: closing the tab ends it.
- **`POST /what-if` reads; it writes nothing.** It is one more route on the loopback server (`scripts/serve-edit.ts`, `scripts/serve-what-if.ts`) and runs four read leaves with the Overrides: `projection run`, `fi`, `projection compare` and, when the Snapshot states a Return model, `projection chance`. Each takes its Overrides as `--without=<path>` and `--set=<path>=<json>` tokens, with `--decimal`, and the argv is built by a pure function (`src/lib/what-if/argv.ts`) that `argv.test.ts` pins. Every argv is a read leaf of the Snapshot allowlist.
- **The guards are the Edit guards.** Host, an Origin equal to that Host, the session token compared in constant time, `application/json`, the 1 MiB body cap and one request at a time. A what-if and an Edit share the busy flag, so either one refused while the other runs answers 409. The body is a closed, strict schema (`src/lib/what-if/overrides.ts`): a plan and its Sets and Removals, with the name rules of an Edit, so no path or id can be read as a flag. Each refusal has its test in `scripts/serve-what-if.test.ts`, and the 1 MiB cap is checked through the real server in `scripts/serve-what-if-server.test.ts`.
- **Each read answers as data.** The answer is the four Reads, each with its argv and its data or its error envelope. A read the CLI refuses (a Set on a path the plan does not hold, a removal a `derive` graph reads) is an error at its own key, and the session is kept. The bar shows the refusal at the change its `details.path` names.
- **Keeping the session is an Edit.** *Save as new plan* is `copy-plan` with its Sets and Removals, which runs `scenario fork <from> <name> --set=… --without=… --decimal` ([cli ADR 0056](../../../cli/docs/adr/0056-a-what-if-takes-a-list-item-out-and-reads-its-amounts-in-major-units.md)). *Apply to this plan* is `apply-overrides`, which runs `scenario apply <name> --set=… --without=… --decimal --if-hash <hash the session began with>` ([cli ADR 0057](../../../cli/docs/adr/0057-a-what-if-applies-to-the-plan-it-came-from.md)). Both are Edits, so they run `--dry-run` first and then read the Snapshot again ([ADR 0008](0008-the-dashboard-edits-scenarios-through-traj-on-loopback.md)). A plan that moved on is refused as `scenario_changed`, and the session is kept, with a Reload that takes the new hash.
- **Revert runs nothing.** It drops the session.
- **Controls show only with the server.** The switches, the *Try a value* actions and the session bar appear only when the server answers the token, and never in the Demo snapshot or under `vite preview`.

## Considered Options

- **A scratch plan in the ledger.** Rejected. Each what-if would be a write the person never asked for, and it would show in `scenario list`. A read with Overrides writes nothing and needs no cleanup.
- **Apply the Overrides in the browser and send the document.** Rejected. The Override grammar of [cli ADR 0024](../../../cli/docs/adr/0024-scenario-documents-and-overrides.md) would be rebuilt in the page, and it would drift from `traj`. `scenario apply --set/--without` applies the same function `projection run` does.
- **Persist the session in the address or in storage.** Rejected for now. A session is one tab's changes, and the issue asks for no link to it.

## Consequences

- The session's reads are never saved to the Snapshot file, and the answer is sent with `Cache-Control: no-store`.
- The page computes no figure. It shows the CLI's values as they come, and the figure pages show a what-if as the amendment below says.
- `POST /what-if` is part of the `traj dashboard` binary, so it ships in a CLI release ([cli ADR 0046](../../../cli/docs/adr/0046-traj-dashboard-edits-scenarios-on-loopback.md), amended).

## Amendment (2026-11-23): the session is bound to its plan, ends when empty, and reads one at a time

- **One gate for the plan.** Every plan change goes through `selectPlan` (`src/client/select-plan.svelte.ts`), never `setQueryParam("scenario", …)`; `what-if.svelte.test.ts` scans `src/` for the latter. While the session holds changes, a switch to another plan asks "Revert and switch" or "Stay". The switches (`isOffIn`, `setOff`) and Try a value (`tryItem`) check the plan too: on another plan they change nothing and ask, so a change can never land in the wrong plan's session, for example after the back button.
- **No change, no session.** The session ends on every path that removes its last change (`WhatIfChanges.keep`), clearing its answer and errors. The bar and its Save and Apply need at least one change.
- **One read at a time.** The server runs one request at a time and answers a second with 409, so `SerialReader` (`src/lib/what-if/reads.ts`) holds at most one read in flight. A change made meanwhile waits and the latest state is read once; a reply for an older state, or for a session that ended, is dropped. A 409 that still comes (an Edit in another tab) is asked again twice. Save and Apply stay disabled while a read is pending or in flight. The bar shows the session's own error, and a refusal that names no change (`unsupported_currency`, `not_found`, `traj_unavailable`, `database_busy`).
- **Clearing a field is not a what-if.** `traj` replaces a path and cannot delete one, so a Try a value that clears a field says so in the drawer and does not close it. Clearing it is the Edit that saves the plan.
- **Body depth.** `POST /what-if` and `POST /edit` refuse a body nested deeper than 32 levels with a 400 in the server's own JSON, before the schema reads it, because a body nested 100000 levels overflowed the schema's stack and Bun answered an HTML 500 page with stack frames.

## Amendment (2026-11-23): every figure page shows the what-if value, the baseline and the change

- **The session's `projection run` takes `--breakdown`**, as every run of the Snapshot does, so the Cash flow page has the what-if's lines and section totals. `argv.test.ts` pins it. No `--liabilities`: no page reads a loan's statement.
- **One lens.** `src/lib/what-if/lens.ts` parses the answer's four reads against the contract (`WhatIfLens`). A read that failed or does not parse is `null`, so a page keeps its baseline for that figure and the session bar shows the refusal. `whatIfSession.lensFor(plan)` returns the lens only for the session's own plan, only while the session holds a change, and only when the reads answer the changes it holds now: a change made after the last reply hides the older answer until the newer one comes. `whatIfSession.changesFor(plan)` gives the planner pages the Sets and Removals on their plan.
- **Three values, one language.** `src/lib/view/what-if/` builds a `Triple` per figure: the what-if value (`sides.b` of the session's `projection compare`, the main figure), the baseline (`sides.a`, secondary) and the change, which is always the CLI's: `deltas.fiMonths`, `deltas.netWorth`, `deltas.atAges`, `deltas.runOutYears`, `deltas.milestones[].months`, or an annual row's `delta`. A change the CLI did not state is shown as "No change stated", with the reason for a screen reader, and is never subtracted in the page. A change has a sign and words ("−3 months, earlier"), never colour alone, and Hide amounts masks all three.
- **Where the CLI states no change, none is shown.** The chance of success is two values ("from 72.00% to 81.00%"). A tax year's due, prepaid and owed, and the cash-flow section totals, are shown beside the baseline with no change; the Levy's change per year is the annual row's. A figure that needs a change the CLI lacks needs it in the CLI first.
- **The planner pages** put the session's Sets and Removals into the plan's document (`src/lib/what-if/overlay.ts`): object editing, as `traj` applies Overrides, with no amount read or changed. A card shows the session's value with the baseline's text struck through, and a switched-off item is dimmed and says "Off in this what-if".
- **Plan binding.** A page shows the session only on the session's plan: the Overview on its primary plan, a plan-agnostic page (Net worth) on the selected plan, the FI date per plan section, and the Compare page when one of its two plans is the session's. With no session, every page renders as before.

## Amendment (2026-11-23): the session can add an item

- **Additions are the third Override.** A session holds, besides Sets and Removals, `additions`: `{ list, item }` with `list` one of `flows`, `accounts` or `milestones` and `item` a JSON object that names itself with an `id` (`src/lib/what-if/additions.ts`). A Levy is not on the list, as in [cli ADR 0062](../../../cli/docs/adr/0062-a-what-if-adds-a-list-item-by-its-own-id-after-the-removals-and-before-the-sets.md).
- **The argv is built in the order `traj` applies them:** every `--without=<path>`, then every `--add=<list>=<json>`, then every `--set=<path>=<json>`, each value one token, with `--decimal`. The item's JSON is after `--add=<list>=`, so it can never be read as a flag; its id still passes the plan-name rules (not empty, no leading `-`, no control character, at most 100 characters). `argv.test.ts` and `additions.test.ts` pin the order.
- **Every guard stays.** Host, Origin, the token, `application/json`, the 1 MiB cap, the depth cap of 32, one request at a time, and a plan name that never starts with `-`. An older page that sends no `additions` is read as none. The body is strict: another list, an item with no id, an id twice or any other field is a 400.
- **Keeping it carries them.** `copy-plan` and `apply-overrides` gain `additions` (default none) and run `scenario fork` / `scenario apply <name>` with the same tokens; an apply or a copy of nothing at all is still refused.
- **The panel lists an addition** by what it is, "Added RMF contribution, 2026" for an allowance's Flow (its label and start year; any other item reads "Added flow <id>"), the id kept in the line's `title`, with its own "Remove this change". A refusal that names the item (`details.path` is `flows.<id>`) shows beside it in the CLI's words, and one that names no change shows at the top of the panel.
- **The planner pages do not draw an added item.** Their cards list what the plan stores; the session panel lists the addition, and the figure pages show its effect.
- **Who adds:** the Tax allowances page's "Try this year as a what-if" ([ADR 0012](0012-the-tax-allowances-page-reads-what-traj-says-each-allowance-could-take.md)). A session on another plan asks first, as a switch does.

## Amendment (2026-11-24): the session can try a Flow

- **A Flow is tried as one unit** (`whatIfSession.tryFlow`): a Flow the plan does not hold is an Addition; an edited Flow is a Set of each changed field; and a change a field Set cannot make (a field removed, such as a spending rule becoming a level amount, or a field the stored Flow did not have, such as an `endAt` for a stop) is one Set of the whole Flow, `flows.<id>` to the edited Flow, which `traj` takes in place of the stored one ([cli ADR 0062](../../../cli/docs/adr/0062-a-what-if-adds-a-list-item-by-its-own-id-after-the-removals-and-before-the-sets.md)). A Removal and an Addition of the same id is never made, because `traj` refuses it. A later try of the same Flow first drops the session's earlier Removal, Addition and Sets of it, so the two never meet. The session bar words a whole-Flow Set in plain words, with no raw JSON.
- **The projection run of a what-if takes `--spending`**, so the Withdrawals page shows the what-if's Rule years beside the baseline's ([ADR 0013](0013-the-withdrawals-page-reads-what-a-spending-rule-pays-and-writes-it-as-one-flow.md)).

## Amendment (2026-11-24): the session can try the estate block

- **The estate block is tried as one Set of the whole object** (`--set estate=<json>`, `whatIfSession.tryChange` with `withTriedEstate`), because a Set of a field cannot add or remove a cost or a gift. `traj` replaces a path the plan holds, so a plan with no block cannot be tried until a first line is saved. The session bar words it "Estate lines tried as edited", with no share or amount.
- **The projection run of a what-if takes `--estate`**, so the Estate page shows the what-if's heirs beside the baseline's ([ADR 0014](0014-the-estate-page-reads-what-heirs-would-receive-and-writes-the-estate-block.md)).

## Amendment (2026-11-24): a loan's or an asset's changes are one group

- **A loan and a real asset change as a whole.** Their parts depend on one another ([cli ADR 0059](../../../cli/docs/adr/0059-a-loan-is-three-document-parts-and-its-statement-is-the-engines.md), [cli ADR 0060](../../../cli/docs/adr/0060-a-real-asset-is-composed-of-existing-parts-and-projection-run-states-each-accounts-value.md)): a loan with no payment is owing for good, and a loan drawn with no purchase is cash from nowhere. The session holds `groups` (`src/lib/what-if/session-group.ts`): a loan or an asset, how it was changed (`off` or `tried`) and the `<list>.<id>` path of each part. A group's Sets and Removals are still ordinary Overrides, so the argv, the server and the Edits do not change.
- **One change in the panel.** The bar lists a group as one change, "Loan boat-loan tried as edited" or "Asset home switched off", and its one "Remove this change" takes every Set and Removal of the group back. A refusal that names any part shows at that change. A later Try or switch of the same group replaces the earlier one, as a Flow's does, and a Try that changes nothing leaves it as the plan stores it.
- **The rule of the switch** is the one deleting follows (`withoutLoan`, `withoutAsset`): every Flow of the item goes (a loan's extra payments too), and so does its debt; an Account the Baseline holds a balance in stays declared, because a Baseline row whose Account the plan does not declare makes every read fail. Items named as the asset's but changed outside the form leave with it. No control offers a part alone: the Income and Expenses lists, the plain Account cards and the read-only loans hold none of them. An item changed outside the form keeps its own switch on those lists.
- **Loan cards show the what-if.** The card takes the session's Sets (`overlayDocument`) and strikes the baseline's text through beside each changed term and the amount borrowed; a switched-off loan is dimmed. The schedule and the amount owing are the plan's own, because the session's `projection run` asks for no loan statement, and the card says so.
