# The Assumptions page sets inflation, each Account's return and swing, and the chance of success's paths and seed

The two assumptions that move every figure in a plan are inflation and what each Account earns, and they were scattered: inflation was edited nowhere in the Dashboard, and each rate sat in its own form. The chance of success now follows them without a model file ([cli ADR 0068](../../../cli/docs/adr/0068-the-chance-of-success-can-draw-from-the-plans-own-return-model.md): `--return-model plan`, built from each asset Account's `rate` and `volatility`). The page puts the plan's market assumptions in one place and lets the person read the chance again. Every figure is the CLI's or the person's own text ([ADR 0002](0002-the-cli-is-the-only-source-of-figures.md)); the page does no arithmetic on money and none on a rate beyond moving its decimal point.

## Decision

- **The page.** `/settings/assumptions/`, "Assumptions" in the Settings group beside the Tax profile ([ADR 0016](0016-the-tax-profile-page-changes-one-item-through-scenario-tax-merge.md)), listed when the plan has a document. It shows the selected plan's values from `scenario show`, already in the Snapshot, so there is no new read leaf.
- **Prices.** Inflation per year as text, saved as `economy.inflation`. The document holds it as an integer of basis points (`traj schema`: "Per year; negative is deflation"), which is how `rate` is held, so the text goes through the same `parseBps` as an Account's rate and is shown with `formatBps`. An inflation left empty takes the `economy` block out of the document.
- **Your accounts.** One row per asset Account, in the document's order, each with `rate` and, for a liquid asset, `volatility`. An illiquid asset (`liquid: false`: a home, a car) shows its return only: the chance of success moves what can be sold, and its stored volatility, if any, is kept as it was. A liability is not listed: it keeps its loan form. Nothing is pre-filled: an inflation or a volatility the plan does not state is an empty field, and an empty volatility says "Empty: fixed at its return in every path", the CLI's own reading.
- **Three plain choices beside each volatility** fill the field with text and nothing else. The person changes the text at once, and the page reads only the field's text on save, so a choice leaves no trace. They are plan assumptions, not advice, and the page says no more of them than what they are:

  | Choice | Fills | For |
  |---|---|---|
  | Steady | 1% | deposits |
  | Moderate | 10% | mixed funds |
  | Large | 18% | shares |

  The reasoning is the long-run spread of yearly returns, which is the quantity a volatility is: the standard deviation of the yearly return. Published long-run histories of share returns (the Global Investment Returns Yearbook's century-long series is one) put the standard deviation of the yearly returns of broad share indices at about 15 to 20%, a mixed fund of roughly 60% shares and 40% bonds varies by about 9 to 11%, and a bank deposit or a short government bill by 1% or less once its rate is stated. The three are rounded to figures a person can remember, one per kind of holding the issue names; none is a forecast, none is the figure for a given fund, and a person who knows their own holding types over it. `traj` ships none ([cli ADR 0068](../../../cli/docs/adr/0068-the-chance-of-success-can-draw-from-the-plans-own-return-model.md)), and the figures live in `src/lib/view/assumptions/choices.ts` with tests that pin their order and kinds, not their wisdom.
- **Saving is one `apply-plan` Edit** with the expected hash ([ADR 0008](0008-the-dashboard-edits-scenarios-through-traj-on-loopback.md)): the stored document with each text moved to basis points (`src/lib/view/assumptions/build.ts`), dry first like every Edit. The page checks only the shape of a text (a percent with at most two places); whether a value is allowed is `traj`'s to say, so a volatility of 150% arrives as the CLI's refusal, in its words. A refusal lands on the row its path names: the path runs through the Account by its id (`document.accounts.<id>.volatility`) or its position (`accounts.<n>.rate`), and `document.economy.inflation` names the inflation field; a path that names none is shown for the whole form. A stale save is refused as `scenario_changed`, with the Reload action. The form is made again when the plan's hash changes, so a Reload never carries an old text over a changed value.
- **A what-if.** "Try as what-if" puts each changed value in the What-if session as a Set ([ADR 0010](0010-the-what-if-session-reads-through-traj-on-loopback.md)): `accounts.<id>.rate`, `accounts.<id>.volatility` and `economy.inflation`. `--set accounts.<id>.volatility` works on an Account with no volatility ([cli ADR 0068](../../../cli/docs/adr/0068-the-chance-of-success-can-draw-from-the-plans-own-return-model.md)). A what-if replaces a value the plan holds, so it cannot try an inflation the plan does not state, and it cannot clear a volatility; the form says each in a sentence and the Edit that saves the plan does the rest. The session's `projection chance` takes the same `--return-model plan` as the Snapshot's, built after the Overrides, so a lower volatility moves the Bands.
- **The chance inputs are the Snapshot's parameters.** The paths and the seed are `params.chance` (`{ source, paths, seed }`, null when none are stated; absent from an older Snapshot, which reads as null) and change through `POST /reread` with `{ "chance": { "paths": 1000, "seed": "<sixteen hex digits>" } }`, as the allowance inputs do ([ADR 0012](0012-the-tax-allowances-page-reads-what-traj-says-each-allowance-could-take.md)); the strict body takes both fields or none, within the CLI's limits (1 to 10,000 paths, sixteen lower-case hex digits). The server keeps the Return model it already holds, which is the plan's own (`plan`) unless a file was given, and changes the paths and the seed. A reread cannot clear them. A page opened with no chance inputs shows both fields empty, and nothing is invented.
- **A reread that changes the chance inputs runs only the chance reads.** This is #442's rule extended, under the same staleness check ([ADR 0012](0012-the-tax-allowances-page-reads-what-traj-says-each-allowance-could-take.md)): the three stage-one reads (the plan list with each plan's content hash, the accounts, net worth at the As-of) run again and are compared, argv and answer, with the held ones; when all three are the same, only the `projection chance` read of each plan runs and is swapped into the held Snapshot with the new inputs, and every other Read stays. When any differs, the body is `{}`, or no Snapshot is held, the whole Plan runs. A body that states both inputs runs both sets of reads. `stillCurrent` takes the kinds of read the reread runs again (`rerun`), so their answers do not count among the kept reads; `withChance` swaps them in (`src/lib/snapshot/reread.ts`, `scripts/run-reread.ts`). The chance reads always match the ledger, because the check covers all their inputs: the plan rows' version and content hash, the account list and the balances at the As-of. On a scratch ledger of one plan, a full read took 9.4 s and a chance change of 1,000 paths took 1.5 s (`scripts/assumptions-reread.test.ts`, which also pins that the partial answer equals the full one byte for byte).
- **The Chance page names its source.** The CLI's `returnModel` echo ("source": "plan", the bucket count and each Account that swings, with its `rate` and `volatility`) is shown as "Built from your plan", with the Accounts it was built from; a read without the echo says "Read from a Return model file" and names the model's id. It needs no Snapshot parameter, so it is right for the Demo snapshot (a file). The empty state of the Chance page points to the Assumptions page.
- **The Demo snapshot does not grow.** It is not rebuilt: `params.chance` is optional in its schema and reads as null. A rebuild would add the object `{source, paths, seed}` (about 70 bytes).
- **The fee column waits.** The account fee form (#410, PR #446) had not merged when this was built, so the page has no fee column; it is added on top of that form's view model once it has.
- **Controls** appear only when the server answers the token, and never in the Demo snapshot, as every Edit control does; in the Demo the page shows the values and the chance's source, read-only.

## Considered Options

- **Pre-fill a volatility, or default the three choices into the field.** Rejected: which risk a plan is tested against is the person's decision, and `traj` ships none. A choice is a button the person presses.
- **A volatility per asset class, from a table of the page's own.** Rejected: it would be a market assumption of the Dashboard's, and the CLI is the only source of figures ([ADR 0002](0002-the-cli-is-the-only-source-of-figures.md)). The three round figures are text a person may change, not data.
- **A full read after a change of the chance inputs.** Rejected: nine seconds, for a change that moves one read; the check already exists.
- **The paths and seed in the plan.** Rejected: a view's settings would become part of the document, as for the allowance inputs.
- **One Try button per field.** Rejected for now: one button tries every changed value together, and a person who wants one tries one.

## Consequences

- A change in the CLI's output fails `src/lib/contract/` and `scripts/contract.test.ts` as before; the chance read's `returnModel` echo is decoded by the contract (cli ADR 0068).
- `scripts/assumptions.test.ts` sets inflation, a return and a volatility on two Accounts in one Edit and reads the Chance page's share and Bands from the plan's model, tries a lower volatility in a what-if (the stored plan is unchanged), adds a volatility to an Account that has none by a what-if, and checks a refusal at its row and a stale save, all against the real binary; `scripts/assumptions-reread.test.ts` pins the partial reread.
- A `traj` older than `--return-model plan` refuses the chance read, which the page shows as the read's own error; the CLI the Dashboard ships with has it.
