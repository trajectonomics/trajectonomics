# The Withdrawals page reads what a spending rule pays, and writes it as one Flow

"How much can I spend each year once I stop working?" follows "when can I stop?". `traj` states a spending rule's years and its spread over Market paths ([cli ADR 0063](../../../cli/docs/adr/0063-a-spending-rule-is-the-engines-fourth-amount-form-and-projection-run-spending-and-projection-chance-state-what-it-pays.md)); the page reads them, writes the rule as one expense Flow, and tries another way in a What-if session. Every figure is the CLI's text ([ADR 0002](0002-the-cli-is-the-only-source-of-figures.md)); no rate, share, band, bound or rounding is a default anywhere in the page.

## Decision

- **Reads.** Every `projection run` of the Snapshot and of a what-if takes `--spending`, so the plan's `spendingRules` table is in the run it already reads (a plan with no rule gets an empty table). The spending Bands and the lowest year come from the plan's `projection chance`, which states them when the plan has a rule Flow. No new read leaf, so `leaves.test.ts` and the CLI's dashboard stub are unchanged.
- **The Flow.** The form writes one expense Flow, `retirement-spending` by convention, beside ADR 0060's ids (`<id>-payment`, `<id>-draw`); the form edits any expense whose `rule` it reads by its id, and a rule it does not read stays as it is, shown as an ordinary expense with the rule in a sentence that holds no amount (`ruleSummary`). The four ways are: a level amount (a plain expense with `growth: "inflation"` and no rule), `initialRate`, `currentRate` (optional steps by date, floor and ceiling) and `guardrails` (a cut, a raise or both; only the raise is labelled "Raise after good years, never cut"). Rates are percent strings as `--decimal` reads them; a floor's and a ceiling's amount are major units, their growth the CLI's (`"inflation"` or `{ bps }`).
- **No default.** No rate, share, band, bound or rounding is filled in, and the way of spending itself is chosen by the person. The form says each rate is the person's own estimate. The rounding select starts on "Choose how to round", "How it is paid" on "Choose how it is paid" and a floor's or a ceiling's growth on "Choose how it grows"; each unchosen one is a problem at its field. A rate is checked for its shape only (digits, at most two places); `traj` refuses the rest at the field its path names.
- **The start.** A Milestone (the plan's retirement Milestone is selected first when there is one: an id that says retire, else the only Milestone an income stops at), or a date, which a household may pin (shown read-only with a link, as the Flow form does). A Milestone start writes `startAt`, and `start` stays the Flow's own start (the As-of for a new one), because recurrence and growth stay anchored on it (sim ADR 0012); a yearly rule therefore pays on the same day each year, counted from the As-of, and the form says so. A `next12Months` Metric beside a rule Flow is refused by `traj` unless the Flow's `startAt` names the Milestone the Metric sits on (sim ADR 0023), and the refusal is shown at the start, in the CLI's words.
- **Other expenses.** When the start is a Milestone the form lists the plan's other expenses still running then (no end, or an end on or after the Milestone's date as `projection run` states it; a one-off paid before that date and a Flow that ended before it are left out), each with "Stop … when this starts"; none is ticked for the person. A ticked one gets `endAt` at the same Milestone in the same `apply-plan` Edit; unticking one the form listed takes its `endAt` of that Milestone back. An expense the form did not list is never touched.
- **Paid from.** The asset Accounts the rule reads, pre-selected as the liquid assets of `cashflow.withdraw`, each removable. A liability and an Account marked `liquid: false` are never offered.
- **Saving** is one `apply-plan` Edit naming the hash the page read ([ADR 0008](0008-the-dashboard-edits-scenarios-through-traj-on-loopback.md)). A refusal lands on the field its path names (`rule.portfolio`, `rule.floor`, `frequency`, `rule.upper`, a Milestone's own path, a stopped expense's `endAt`), shown in the CLI's own sentence for the five `RULE_*` codes and `NEXT_12_MONTHS_READS_ACCOUNT`. `RULE_NOT_EXPENSE` cannot be made by the form, which writes only expenses.
- **Try as a what-if** ([ADR 0010](0010-the-what-if-session-reads-through-traj-on-loopback.md), amended). A new Flow is an Addition. An edited rule of the same kind is a Set of the Flow's changed fields (the whole `rule` object is one Set, so a removed floor is a replaced `rule`, not a delete). A change a Set of fields cannot make (a rule becomes a level amount, the Flow gains a field it did not have such as `endAt` for a stop, or a Milestone start replaces a date) is one Set of the whole Flow, `flows.<id>` to the edited Flow, which `traj` takes in place of the stored one and checks like any plan; a Removal with an Addition of the same id is refused by `traj` (cli ADR 0062) and is never made. If a household pins the Flow's start or end and the edited Flow omits it, the try is refused with a plain note, because the what-if would lack a date that saving fills back in. The session bar words a tried Flow (the rule kind and share, the Accounts by name, never a figure or raw JSON). A later try of the same Flow replaces the earlier one. The page then shows the what-if's years and Bands above the saved plan's, chance included.
- **The Expenses page** shows a Flow that starts or stops at a Milestone as "When <id> fires" (the Milestone's id) in place of its own `start` or `end`, which for a rule saved here is only the As-of recurrence counts from.
- **The page.** The Rule years per rule Flow, nominal or in today's money (`realAmount` and `realPaid`) or both, from the address bar's `terms`: the amount, what was paid, the savings read, the share as the CLI states it (`withdrawalRate`, not capped, absent on an empty portfolio and said so), and what the rule did in words (none, floor, ceiling, cut, raise), a marker on every year the rule moved the amount. Under it, the chance of success, the spending Bands drawn with the net-worth fan, and "In the worst years you would spend", each level in plain words with the CLI's lowest-year amount and how many paths it counts (a path that ran out counts 0; a part year is not a whole year). Hide amounts masks every amount and the Band axis. The Bands are nominal, as the engine states them.
- **Navigation and Home.** Withdrawals is `/optimize/withdrawals/` in the Optimize group, listed when the selected plan has a document. The Home card "You could spend" states the first Rule year's amount and its share, only when the run states a rule year.
- **The Demo.** (Amended by [ADR 0014](0014-the-estate-page-reads-what-heirs-would-receive-and-writes-the-estate-block.md): the horizon is now 2053 and the figures below moved.) `base` of the Demo has a guardrails rule from 1 June 2050 over the bank and the fund (4%, rounded down, a tenth cut or raise beyond a fifth), added after `retire-early` is forked so only `base` has it. The snapshot is 1,028,272 bytes, under Biome's 1 MiB formatter limit, so nothing in the Demo was shortened. One pinned figure moved: the FI date of `base` is Jul 2041 (it was Feb 2041), because the FI method is `survival`: the rule from 2050 makes surviving to the horizon harder, so the date moves later (`fi --scenario=base` gives 2041-07-01, and 2041-02-01 with `--without=flows.retirement-spending`). It does not enter the next twelve months of spending the reference reads.

## Considered Options

- **Pre-select a way to spend, or a usual rate.** Rejected: a default reads as advice, and `traj` ships none.
- **Write the rule's start as a computed date.** Rejected: a Milestone's date moves with the plan, and the page does no date arithmetic.
- **Set every field of the edited Flow in a what-if.** Rejected: a Set of a field replaces an existing path and cannot add or delete one. Not a Removal and an Addition of the same id either: `traj` refuses an id both taken out and added in one call (cli ADR 0062). A change a field Set cannot make is one Set of the whole Flow.
- **A line chart of the years.** Deferred: the table states every figure the CLI does; the Bands are the picture the issue asks for.

## Consequences

- A change in the CLI's output fails `src/lib/contract/projection-run.test.ts` and `projection-chance.test.ts` (their goldens), and `scripts/withdrawals.test.ts`, which works one rule year by hand against the real binary: savings of 1,398,900.00 less 5,000.00 of rent and 500.00 of gym are 1,393,400.00 on 1 June 2027, 4% is 55,736.00, and stopping the gym at the Milestone leaves 1,337,664.00 for the next year instead of 1,336,464.00.
- A `traj` older than the spending rule refuses `--spending` as an unknown flag, which fails the Snapshot's run reads; the CLI the Dashboard ships with has it.
