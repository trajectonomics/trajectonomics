# Dashboard

A read-only web app, in this repository, that shows what `traj` already computed. It runs from a checkout on `127.0.0.1` and reads one Snapshot file.

## Language

**Dashboard**:
The static web app in `apps/web`: Svelte 5 pages and components that render one Snapshot and compute no figure of their own.
_Avoid_: backend, API, sync, server

**Snapshot**:
One JSON document, version 1, that holds every Read the Dashboard needs, each with the argv that produced it. It is the closed contract between `traj` and the Dashboard.
_Avoid_: backend, API, sync, server, payload, cache

**Read**:
One `traj … --json` call, kept verbatim in a Snapshot: its argv and either its parsed data or its error envelope.
_Avoid_: fetch, request, query, call

**Demo snapshot**:
The Snapshot in `public/demo/snapshot.json`, built from a fictional ledger, so the Dashboard can be seen with no ledger of anyone's own. It is generated by `bun run demo` (Turborepo's `demo` task) and never committed ([ADR 0021](docs/adr/0021-the-demo-snapshot-is-generated-at-build-and-not-committed.md)).
_Avoid_: sample data, mock, fixture, seed data

**Hosted Demo**:
The second build target of the Dashboard (`bun run build:hosted`, output `dist-hosted/`), served by the Site under `/demo/`. It reads the Demo snapshot only, has no edit client, and shows each Edit control switched off with a sentence that points to `traj dashboard` ([ADR 0028](docs/adr/0028-the-hosted-demo-is-a-second-build-target-with-no-edit-client.md)).
_Avoid_: live demo, web app, playground, sandbox

**Twin**:
A module in `src/hosted/` that stands in for one module of the loopback build when the hosted target is built. The closed list of twins is `src/hosted/overrides.ts`.
_Avoid_: mock, stub, polyfill, fork

**Fence**:
The one component (`HostedFence`) that switches off every Edit control of the Hosted Demo and sets each one's title. A control it does not know is switched off.
_Avoid_: lock, guard, overlay

**Pack**:
The built pages of `dist/` in one file, `pack/dashboard.bin`: every file's bytes in base64 by its path, in one JSON document. The compiled `traj` embeds it so `traj dashboard` can serve the Dashboard without a checkout.
_Avoid_: bundle, archive, assets

**Plan**:
The list of argv a Snapshot needs, computed from the parameters alone. Stage one reads the Scenarios, the accounts and the first transaction date; stage two reads everything else.
_Avoid_: pipeline, workflow, job, script

**Edit**:
A write the page asks the server to run: one of a closed list (`src/lib/edit/edit.ts`) of `traj` writes, copy a plan, apply a Scenario document, delete a plan, rename it, keep notes on it, mark the main plan, or record values in the ledger. The server runs it dry, then for real, then re-reads the Snapshot, and answers with the new Snapshot (and, for recorded values, what `traj` stated) or the CLI's error envelope.
_Avoid_: save, mutation, update, PATCH, request, write

**Value sheet**:
The drawer on the Net worth page, "Record today's values": one row per open asset and liability Leaf Account, grouped by the top-level account each asset sits under (or "Assets" when it has no parent) and "Debts", each with its last Balance, the date of its last Transaction and a field for today's value. A row with a typed value is changed, and Save sends every changed row as one `record-values` Edit. The page sends the text as typed and shows `before → value` and the difference as `traj` stated them.
_Avoid_: form, reconciliation, balance update

**Count against**:
The income or equity Leaf Account that a recorded value's difference is counted against, chosen once from the ledger's own accounts and kept for the session. The page never makes one: with none, it shows the `traj account add` command to run.
_Avoid_: offset, contra account, source account

**Balance history import**:
The three-step drawer on the Net worth page, "Import a balance history", that turns a spreadsheet into one `record-values` Edit: **Load** (pasted text or a CSV or TSV file, in one of three layouts, with a required header row), **Match** (each account of the table matched to a Leaf Account of the ledger, or skipped) and **Review** (the count, the dates, the Count against account and a Preview). The page reads the text and converts no amount; a date it cannot read unambiguously is a row to fix, and a Buddhist-era year is read as input and never written. Nothing is written until Import, and Cancel forgets the draft.
_Avoid_: upload, sync, migration, bulk edit, reconciliation

**History cap**:
The most month-ends the Net worth history holds, 120 (ten years), stated by one `report networth --monthly` read. A ledger that reaches back further keeps the latest 120, and the page says where the ledger really starts. It is a limit on the months one read states, not a date the page computes (web ADR 0027).
_Avoid_: window, zoom, range (the Plans page's Range is a different control)

**Preview**:
The `record-values` Edit with `preview: true`: the server runs `traj`'s dry run only and answers its result, with no write and no new Snapshot. The Review step shows it as what would be recorded, or every refused value at its row and column in the table.
_Avoid_: simulation, validation, test run, draft

**Account name**:
The name the ledger gives an Account (`traj account list`), which every page shows in place of the id the plan holds it by. One lookup (`src/lib/view/account-names/`) is built from the Snapshot's accounts Read and nothing else, so a rename in the ledger shows once the Snapshot is read again. The ledger keeps names unique (`account_name_taken`); this only guards a Snapshot that breaks that: two Accounts that share a name are shown with their parents, the fewest that tell them apart ("Bank A › Savings"), and with the tail of their id when even the parents agree. An id the ledger does not name (an Account only the plan has, such as a home it buys) shows as the id, in code. Pickers keep the id as the value and show the name as the label, and an Edit still sends ids.
_Avoid_: label, alias, display name

**Item name**:
The words a page shows for the id of a plan item, from one lookup (`src/lib/view/item-names/`, [ADR 0029](docs/adr/0029-plan-items-are-named-by-what-a-read-states-and-never-made-up.md)). A Read states a name for an Account (the Account name), for a person of the household (the `displayLabel` it states, else the role: "You", "Your partner", "Child"), and for a Flow and a Milestone (the `displayLabel` the plan's document states). An item that states no label shows its id in code, and the page never turns an id into words. Pickers keep the id as the value and an Edit still sends ids.
_Avoid_: label, display name, title, alias

**Household**:
The people a Scenario's dates are pinned to: one account holder, at most one partner, and any dependents, each with a birth month and a life expectancy. Its anchors write a date into a Scenario item, so the Dashboard shows the age it is pinned to. The page computes no age.
_Avoid_: family, members, users, profile

**Anchor**:
One date of a Scenario item pinned to a person's age, life end or joining. The label reads "at you, age 60" (the person called by the household's words, an Item name), and the date is the one the household wrote.
_Avoid_: link, rule, trigger

**Milestone**:
A named target in a Scenario that fires on a date, on another Milestone, or when a figure such as net worth passes a level (sim ADR 0012). The Dashboard shows the date `traj projection run` reports for each one, or that it is not reached; it never works one out.
_Avoid_: Goal, event, target date

**Cash flow**:
The lines and section totals of one Annual roll-up, as `projection run --breakdown` states them: where a year's money came from (income, withdrawals, money drawn) and where it went (tax, spending by category, saving per Flow, money left over), with any Shortfall as unmet.
_Avoid_: budget, ledger, transactions

**Flow diagram**:
The picture of one year's cash flow on the Cash flow page: sources on the left, the cash node, and uses on the right, with each band's height its amount's share of the taller column. Pure geometry from `src/lib/chart/flow.ts`; it adds no figure of its own. Below the `md` breakpoint the page draws the same year as two lists of bars instead (sources above, uses below, on one scale), from `src/lib/chart/flow-stack.ts` ([ADR 0019](docs/adr/0019-the-cash-flow-page-stacks-its-diagram-on-a-phone.md)).
_Avoid_: Sankey (as a name for the page), chart, graph

**What-if session**:
The changes one tab holds against one plan, switched items off (Removals) and values set (Sets), which `traj` applies transiently to read a figure and never writes until the person keeps or applies it. It is held in the tab only.
_Avoid_: scratch plan, draft, scenario copy, simulation

**Group** (in a What-if session):
A loan or a real asset changed as a whole: its parts (Account, Flows, debt) are switched off, tried and taken back together, and the session bar lists them as one change. A part never changes alone, because the plan would not agree with itself. A path is in at most one group, and a debt the Baseline holds has no switch.
_Avoid_: bundle, batch

**What-if lens**:
What a page may show of a What-if session, on the session's plan only. For a figure page it is the four reads of the session's answer, parsed against the contract and bound to the plan (`WhatIfLens`, whose reads are `LensReads`); for a planner page it is the plan's document with the session's changes put in (`lensDocument`). A page with no lens shows the baseline alone, and its markup is the markup it has with no What-if at all.
_Avoid_: preview, overlay, diff, what-if reads (for the lens's reads)

**Loan**:
A liability Account in a plan, with the level Contribution that repays it and, when the money arrives on a date, the withdrawal that borrows it. The page edits the three parts together; `traj` computes the payments and the statement.
_Avoid_: debt schedule, amortization, mortgage (as a kind)

**Report**:
A table of the selected plan's projection as `traj` stated it, which the Reports page previews and writes as a CSV or JSON file, or prints. A CSV cell is exactly the string the Snapshot holds, and an empty cell is a figure `traj` stated as null. A cell is never guarded against a spreadsheet formula: the data is the person's own ledger, and a guard would change what `traj` stated. The JSON is value-equal to the Snapshot's Read, not byte-identical, because the loader keeps the parsed result and not the file's text.
_Avoid_: export (as the name of the table), statement, extract

**Real asset**:
An asset Account that is not liquid (a home or a car), with the items that buy, finance, keep, rent out and sell it, written under one id convention. The page edits them together and groups them on one card; `traj` computes its value, its costs and its loan. An item that follows the convention's id but not its shape is an ordinary item.
_Avoid_: property, holding, fixed asset (as a kind)

**Addition**:
A new list item (a Flow, an Account or a Milestone) that a What-if session puts on the plan with its own id, which `traj` applies after the Removals and before the Sets (`--add`) and never writes until the person keeps or applies the session. The page sends the item as one argv token and lists it in the session with its own way to remove it.
_Avoid_: new item, insert, patch

**Allowance inputs**:
The labels in the person's order, the step and the two optional limits (a yearly budget, a least saving per step) that the `projection allowances` reads are made with. They are kept with the Snapshot's parameters and never in a Scenario, so changing them is a read and writes nothing.
_Avoid_: settings, preferences, options

**Suggestion**:
One Flow `traj projection allowances` states for a tax year and an allowance: a lump contribution of the extra that fits, with the Account it pays into, or a hint of why it has none. The page never makes one; it tries it as Additions or adds it to the plan.
_Avoid_: recommendation, advice, tip

**Spending rule**:
An expense Flow with a `rule` in place of an amount: a share of what the plan's savings are worth, kept level, or taken each year, or taken with limits that cut and raise. The rate, band, bound and rounding are the person's own estimate and `traj` ships none. The page writes it as one Flow and reads what it pays from `projection run --spending`; it computes no amount of one.
_Avoid_: withdrawal strategy, safe withdrawal rate, drawdown

**Rule year**:
Twelve monthly occurrences, or one annual one, of a spending rule, counted from the Flow's first landed date. `traj` states for each the savings the rule read, the amount it fixed, what was paid (nominal and in today's money), the share of the savings and what the rule did (none, floor, ceiling, cut, raise).
_Avoid_: fiscal year, spending year (as a calendar year)

**Spending Bands**:
The Percentiles across Market paths of what a spending rule pays in each roll-up, and of each path's lowest whole year, as `projection chance` states them. A path that ran out counts 0, and a part year is not a whole one.
_Avoid_: forecast, range of outcomes

**Estate**:
What the plan would leave on one date, as `projection run --estate` states it: the gross estate (everything owned), the debts, the settlement costs, the net estate, the gifts and what heirs receive, with each cost and gift line. Only the net estate and what heirs receive are also stated in today's money. Every cost and gift is the person's own, written in the plan's `estate` block; no tax is worked out, and an inheritance tax is a cost line the person types.
_Avoid_: inheritance, will, legacy, probate

**Estate date**:
The date the Estate page reads: the later life expectancy of the household's holder and partner by default, a Milestone, a household anchor or the plan's last year. The page reads the `estate` row on that date or the first roll-up end after it, and computes no date.
_Avoid_: death date, payout date

**Tax profile**:
The items a plan's tax assumes about the person (filing status, children, parents, disabled care and the deductions paid in the tax year), as `scenario show` states them in `tax`. They are the person's inputs, not figures: the Dashboard shows them as stored and sends a change as one `scenario tax` write.
_Avoid_: tax settings, tax return, tax rules

**Filer**:
A person a joint Tax Levy files for: the household's holder or partner who has income, named by the Filer label suffix `@<person id>` on the tax labels of the Flows and Accounts they own, with `@shared` for what both own (cli ADR-0075). A plan without a partner or Owners has no Filers and bare labels.
_Avoid_: taxpayer, spouse

**Return**:
One Filer's Thai tax Levy of a separate filing, `th-2026-pit@<person>`, with its own taxable income, allowances, tax and prepayments as `traj` states them. The Tax page shows one Return at a time, chosen by a switch named by the household's role ("You", "Your partner"). A joint or single plan has one Return and no switch; a profile that files separately states each Return's claims in `returns` (cli ADR-0075).
_Avoid_: tax return, filing, declaration

**Who claims each allowance**:
The table on the Tax profile page of a separate filing: one column per Return and one row per allowance, each cell the amount that Return's profile claims, from `returns`. It is what the profile stores, never what the tax rules applied, and the CLI's note on a shared home loan's ceiling shows under it when it states one.
_Avoid_: allowance split, allocation

**Assumptions**:
The figures a plan rests on that are the person's own, in one place: inflation per year, and each asset Account's expected yearly return and swing. They are the document's `economy.inflation` and each Account's `rate` and `volatility`, saved as one `apply-plan` Edit. None is filled in for the person: `traj` ships none, and nor does the page.
_Avoid_: settings, parameters, defaults, market data

**Swing**:
How much an asset Account's yearly return varies, as the standard deviation of that return in percent (`volatility`, an integer of basis points in the document). Only the chance of success reads it. An Account with none is fixed at its return in every Market path.
_Avoid_: risk, volatility score, beta

**Swing choice**:
One of three plain buttons beside a swing field (steady such as deposits, moderate such as mixed funds, large such as shares) that fills the field with a round percent. It holds no state of its own: the person changes the text at once, and the figure is a plan assumption, not advice.
_Avoid_: risk profile, preset, risk level

**Chance inputs**:
The number of Market paths and the seed the chance of success is read with. They are the Snapshot's parameters, not the plan's, changed through `POST /reread` as the allowance inputs are, so a change reads again and writes nothing.
_Avoid_: simulation settings, iterations

**Model source**:
Where a chance read's Return model came from: built from the plan (the CLI's `returnModel` echo, "built from your plan") or read from a file the Dashboard was started with.
_Avoid_: engine, data source

**Future**:
One seeded Market path of a chance read, named by its index under the run's seed and numbered from 0 as `--index` numbers it. The Chance page lists every one (closing net worth, lowest point, when it ran out or that it lasted) and opens one year by year on its own page, a replay of exactly that path (`projection path`). It is the CLI's replay, never a simulation of the page's.
_Avoid_: scenario, simulation, run, trial, outcome (as the name of the page)

**Futures worth a look**:
The cards for the CLI's five `representative` paths: a bad future (10th percentile), a typical one, a good one, the earliest run-out and the deepest fall. The Snapshot reads each in advance, so the Demo and an offline Snapshot could open them.
_Avoid_: top paths, samples, highlights

**Path read**:
The read of one future through `POST /reread` with `{ path: { plan, index } }`, for an index the Snapshot did not read. It answers that one Read and leaves the Snapshot, the parameters and the ledger alone, and it is shown only if it is of the chance on screen (the same model, seed, paths and plan content).
_Avoid_: reread (it rereads nothing), fetch, simulate

**Tax group**:
One of the six cards the Tax profile page shows (filing status, family, insurance, home, giving, social security), each holding the profile items of its group and an Edit that opens the drawer on them. A deduction class `scenario tax` reports is placed in a group by `PLACE` in `src/lib/view/tax-settings/groups.ts`; the two retirement classes are stated by contribution Flows and sit in no group.
_Avoid_: section, category, tab

**Not in your plan yet**:
The deduction classes `scenario show` reports as not stated for the stored profile (`taxAllowances.notStated`, the list `scenario tax` reports as `allowances.notStated`), listed under the cards. Each opens the drawer on its group, except the two retirement classes, which link to the Tax allowances page.
_Avoid_: missing deductions, unused allowances

**Tax label**:
The Tally label an income Flow carries so that the tax rules read it. A taxed plan takes a label on a Flow in the Tax labels form (an `apply-plan` Edit); a plan with no tax takes its labels in the `set-tax` write that gives it tax, because `traj` writes a label only beside a Levy.
_Avoid_: tag, category, income type

**Custom chart**:
A chart a person made of yearly figures `traj` states, a name, a kind and a list of series ids, kept in the browser and in no plan. A series a plan lacks is named as missing, not drawn.
_Avoid_: report, widget, dashboard, saved view

**Employer's share**:
What an employer pays into an Account on top of a salary: one Contribution Flow with `funding: "employer"` that reads the salary's gross. It lands in the Account outside the household's cash and stops with the salary, so it is no income and no spending. The page writes it with the salary in one Edit and keeps the two in step.
_Avoid_: match, employer contribution (as a Flow kind), PVD

**Payout**:
A yearly share of an asset Account's value that leaves it on the last day of each period and lands as passive income, from the Account's `payout` field. The share, the period, the start and the rounding are the person's own; `traj` ships none.
_Avoid_: dividend (as the name of the field), distribution, withdrawal

**Account fee**:
A yearly share of an asset Account's value charged a twelfth a month, outside cashflow, on every Market path, from the Account's `fee` field. The page lists each roll-up's charge as `traj` states it and adds none up.
_Avoid_: cost, charge (as the name of the field), expense


**Tax walk**:
How a tax year's assessable income became its taxable income, as the Levy's own measures state it and `taxYears[].walk` carries it: assessable income, less expenses, less allowances, equals taxable income. The Tax page lists the four figures for the current tax year and adds none.
_Avoid_: calculation, tax computation, waterfall

**Bracket bar**:
One bar of the Tax page's card of brackets, for each progressive bracket the taxable income reached: its rate, the income taxed in it and its tax, as `taxYears[].brackets` states them. The bar's width is that bracket's income against the largest bracket's, for drawing only. The last bar is marked "Your top rate".
_Avoid_: tier, band, slab

**Top rate**:
The rate of the bracket the last baht of taxable income falls in (`marginalRateBps`), so what one more baht of income, or one baht less through an allowance, is worth in tax. The CLI reads income exactly on a bracket's edge as in the bracket it closes, and states `toNextBracket` as the taxable income left before the next rate; the highest bracket has none.
_Avoid_: marginal tax rate (in a heading), bracket rate

**Share of income paid in tax**:
The tax due as a share of assessable income (`effectiveRateBps`), before expenses and allowances. It is absent when nothing was assessed.
_Avoid_: effective rate (in a heading), tax rate, average rate

**Routing**:
The plan's `cashflow` read as three lists the Where money goes page edits: the surplus steps (what happens to money left over), the `contribute` priority (which savings come first) and the `withdraw` entries (what is drawn when money is short). A step and an entry are addressed by position, since neither has an id.
_Avoid_: waterfall, allocation, priority list

**Surplus step**:
One row of "When there is money left over": an Account, and everything, an amount it fills up to, or a share of what is left. The last step must take everything.
_Avoid_: bucket, rule

**Reserve floor**:
The amount an entry of `withdraw` stops taking an Account down to, while later entries are used first. Setting one adds a later entry that takes the rest of the Account.
_Avoid_: minimum balance, emergency fund (as the name of the field)

**Target in today's money**:
An amount of a step or a floor that keeps its value: `{ amount, growth: "inflation" }`. The page shows the document's amount and what the routing echo says of it, never a grown figure of its own.
_Avoid_: real target, indexed amount

**Planned move**:
A `transfer` Flow: money moved between the plan's own Accounts, or onto a loan, outside income, spending and saving. It changes no net worth, and counts a gain for tax only when `realise` is on.
_Avoid_: rebalance, switch, transfer (as a page word)

**Main plan**:
The one plan the ledger marks as the person's real plan (`scenario main`). It is a label and not a default for a `traj` read: the Dashboard lists it first, opens its pages on it, and Home follows it unless the address bar names another plan.
_Avoid_: default plan, primary plan, active plan

**Plan notes**:
The plain text a plan keeps about what it assumes (`scenario notes`), outside the Scenario document and its hash. A card shows the first line and opens the rest; the switcher shows a notes icon beside a plan that has some.
_Avoid_: comment, description, memo

**Plans page**:
`/plans/`: one card for each plan the dashboard projects, side by side, the main plan first and then by name. A plan the ledger holds that the dashboard was not started with is listed by name as not projected, with an action to add it.
_Avoid_: compare page, plan list, portfolio

**Range**:
The control of the Plans page that narrows every chart to the first 10, 20 or 30 yearly rows of its plan, or shows the whole plan. It chooses which of `traj`'s rows are drawn and computes no date or figure.
_Avoid_: zoom, period, window
