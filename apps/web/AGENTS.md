# AGENTS.md

Read the root [AGENTS.md](../../AGENTS.md) first. This file holds only what is specific to `apps/web`, the Dashboard: a static web app that renders a Snapshot of `traj --json` results and sends Edits, each one a `traj` write. It is Svelte 5 on SvelteKit ([ADR 0006](docs/adr/0006-svelte-5-on-sveltekit-replaces-astro-and-react.md)).

## Rules

1. The CLI is the only source of figures, and the only writer. The Dashboard never imports a core to compute, never does arithmetic on money, and shows the CLI's decimal strings as they are ([ADR 0002](docs/adr/0002-the-cli-is-the-only-source-of-figures.md)). A string may be parsed to a number only to place a mark on a chart, in `toChartNumber` in `src/lib/chart/`. A change to a plan, or a value recorded in the ledger, goes through an Edit, which is one `traj` write; the page itself never writes a file or the ledger ([ADR 0008](docs/adr/0008-the-dashboard-edits-scenarios-through-traj-on-loopback.md)).
2. `src/lib/` is pure: data in, data out, no I/O, no clock, no `Date`, no `process`. Spawning `traj`, reading and writing files, and the command line live in `scripts/`. The browser (storage, the address bar, `fetch`, the document) is reached only from `src/client/`. The Snapshot plan (`src/lib/snapshot/`) emits read leaves only, and `leaves.test.ts` pins that allowlist. The Edits are a separate closed list in `src/lib/edit/`, which `edit.test.ts` pins: each one maps to one `traj` write (a `scenario` write, or `account value` for `record-values`, which also takes `preview` to stop after the dry run), and nothing else runs.
3. Dates come from the caller (`--as-of`, `--horizon`), never from the machine ([cli ADR 0029](../cli/docs/adr/0029-reads-take-their-date-from-the-caller.md)).
4. The Dashboard runs on `127.0.0.1` only: from a checkout with `bun run dashboard`, and for everyone else through `traj dashboard`, which embeds `pack/dashboard.bin` and runs `scripts/serve.ts` ([ADR 0007](docs/adr/0007-traj-dashboard-serves-the-dashboard-on-loopback.md)). Do not add hosting, a Worker, a `wrangler.jsonc`, a deploy job or a server that listens beyond loopback without the owner ([ADR 0004](docs/adr/0004-no-server-and-no-hosting.md)). The one exception is the hosted Demo on the Site ([ADR 0009](docs/adr/0009-the-demo-dashboard-is-hosted-on-the-site.md)): static pages that read the generated Demo snapshot and nothing else, with no upload and no Edit. `scripts/serve.ts`, `scripts/serve-edit.ts` and `src/lib/serve/` ship inside the CLI binary, so keep the Host check and the `no-store` headers. The write path has its own guards in `src/lib/edit/guard.ts`: Host, an Origin equal to that Host, the session token (compared in constant time), `application/json`, a 1 MiB body cap and one Edit at a time. A plan name never starts with `-`: `traj` does take `--` (its reads use it), but an Edit's argv puts the name before its flags and without `--`, so a leading `-` would be read as a flag. Each refusal keeps its test in `scripts/serve-edit.test.ts` or `src/lib/edit/guard.test.ts`, and a change to one is a change to a published binary ([cli ADR 0046](../cli/docs/adr/0046-traj-dashboard-edits-scenarios-on-loopback.md)).
5. The contract in `src/lib/contract/` follows `traj schema <leaf> --json`. Take every field from that output, never from memory. A change in the CLI's output must fail `scripts/contract.test.ts`, which builds a ledger with the workspace `traj` binary.
6. Done means `bun run check` passes in `apps/web`: Biome lint with zero warnings, `svelte-check` and the strict typecheck with warnings as errors, the tests (including the Svelte guard) and the Vite build. Do not loosen `tsconfig.base.json`, `biome.json` or the shared config to make an error go away. CI runs the same steps as separate jobs and splits the `scripts/` tests across shards ([docs/runbooks/ci.md](../../docs/runbooks/ci.md)): a step added to `check` or to the tests needs a matching change in `.github/workflows/ci.yml`, and `tooling/guards` fails until it has one.
7. The Demo snapshot (`public/demo/snapshot.json`) is generated and never committed ([ADR 0021](docs/adr/0021-the-demo-snapshot-is-generated-at-build-and-not-committed.md)). `bun run demo` (Turborepo's `demo` task) writes it as compact JSON, and `build`, `test`, `test:src`, `test:scripts` and `check` depend on that task, and `bun run check` in `apps/web` runs it too. A fresh clone runs `bunx turbo run demo --filter=@trajectonomics/web` (or `check`) before `bun test`; a test that finds the file missing says so. Read the file through `scripts/demo-snapshot.ts` (`demoSnapshotText`, `demoSnapshotJson`), never `Bun.file(...)` on the path, so the error stays the same. Do not commit the file, and do not add it to `biome.json`: `.gitignore` is enough. The task builds its own `traj` without the Pack, so do not make it depend on `@trajectonomics/cli#build`: that is a cycle through `web#build`. Two runs write the same bytes: the task compiles the CLI's `src/demo-entry.ts`, which honours `TRAJ_FIXED_SOURCE` (a fixed clock and counted UUIDv7 ids, [cli ADR 0074](../cli/docs/adr/0074-the-demo-is-generated-by-an-entry-point-with-a-fixed-clock-and-counted-ids.md)), and `scripts/demo-regeneration.test.ts` fails when they drift. Never rewrite an id in the generator: the content hashes cover them, and a saved chart's series keys (`account:<uuid>`) must survive a regeneration.
8. The browser checks (`browser/`, [ADR 0026](docs/adr/0026-a-headless-browser-checks-the-demo-at-phone-width-and-in-print.md)) run a headless Chromium over the built Demo: every page at 360px and 1280px in both themes, and Reports, Projection and Cash flow in print on A4. CI runs them as `Check web browser`; `bun run check` does not. To run them locally, build first, then run the script: `bunx turbo run @trajectonomics/web#build` at the repository root, `bunx playwright install chromium` once, then `bun run test:browser` in `apps/web` (`TRAJ_WEB_BROWSER_PORT` moves the port from 4391). The screenshots land in `screenshots/` (ignored by git). A page you add is checked without an edit, because the pages are read from `src/routes/`. The checks are rules, never pixel comparisons: a wide table sits in a `relative` scroll box (`relative max-w-full overflow-x-auto`, so the screen-reader-only labels in its cells stay inside it), and printing must stay black on white and fit 1032px (A4 landscape, 12mm margins). The suite pins Liberation Sans (installed by `playwright install-deps`) and fails when it is missing, because the widths depend on the font. Fix the page, not the rule.
9. Keep to the vocabulary in [GLOSSARY.md](GLOSSARY.md). A Snapshot is not a "backend response", and a Read is not a "fetch".

## Svelte 5: how to write a component

The Svelte 5 docs are the reference, and they are current: read them, not your memory of Svelte 3 or 4. Fetch `https://svelte.dev/docs/svelte/llms.txt` for the language (runes, snippets, event attributes, `.svelte.ts` modules, `render` from `svelte/server`) and `https://svelte.dev/docs/kit/llms.txt` for SvelteKit (page options, `$app/state`, `$app/navigation`, the static adapter).

- **Runes only.** Props are `let { a, b = 1 }: Props = $props()`; state is `$state`; a value computed from others is `$derived` (or `$derived.by`). Never `export let`, `$:`, `$$props`, `$$restProps` or `$$slots`.
- **Snippets, not slots.** A child is a `children: Snippet` prop, rendered with `{@render children()}`. A named piece of markup is a `{#snippet name()}…{/snippet}`.
- **Event attributes.** `onclick={handler}`, `onkeydown={…}`, never `on:click`.
- **Every `<script>` is `lang="ts"`.** A component is at most 100 non-blank lines; split it when it grows.
- **Shared reactive state is a `.svelte.ts` module under `src/client/`** that exports a class instance or a `$state` object. Never a Svelte store (`svelte/store`), and never a reactive `let` exported from a module (it is not reactive for an importer).
- **`$effect` only to touch the browser.** Anything computed is `$derived`. The shell starts the Snapshot read in an `$effect` that follows the address, so a switch to `?demo=1` loads the Demo snapshot.
- **Page logic stays in the pure view models in `src/lib/view/`.** A component only renders: it takes the view model's values as props and places them.
- **A component takes props.** It reads `$app/state` only when it is a route file (`src/routes/`) or part of the shell (the root layout and `src/components/shell/`). Components below the shell read the address through `src/client/location.svelte.ts`, and the Snapshot through `src/client/snapshot.svelte.ts`.
- **Query-string state** (such as the Scenario a page shows) is read in a route file with `queryParam` and set with `setQueryParam` from `src/client/query-param.svelte.ts`. The helper replaces the entry and does not load.
- **Tests render to a string** with `render` from `svelte/server`, after `bunfig.toml` has preloaded the compiler. A snippet a test passes is made with `createRawSnippet`. `$app/*` resolves to `scripts/svelte/app-stub.ts`, where a test sets the address with `setTestUrl`.

## The guards, and how to read a failure

- **Runes mode** (`vite.config.ts`, `compilerOptions.runes`). A Svelte 4 form fails the compile, in `svelte-check` or `vite build`: `Cannot use export let in runes mode — use $props() instead`. Write the form it names.
- **`svelte-check --fail-on-warnings`** (`bun run typecheck`). A deprecated form that still compiles, such as `<slot>` or `on:click`, fails here as a warning, and so does a symbol that is declared and not used, which Biome cannot see in markup.
- **The Svelte guard** (`bun test`, `scripts/svelte-guard.test.ts`). It prints `file:line [rule] message`, for example `Money.svelte:2 [money/number-conversion] …`. The message names the Svelte 5 form to write. The rules are in `src/lib/guard/`, one file per kind of rule, each with a bad and a good example in `rules.test.ts`. A plain `.ts` module under `src/` is held to the boundary rules too (no store, no React or Astro, no browser call outside `src/client/`), so a forbidden call cannot hide in a helper.
- **The dependency guard** (`scripts/dependency-guard.test.ts`) fails when the package lists `react`, `react-dom`, `astro` or any `@astrojs/*` package. React is allowed in this repository only in `apps/docs`, for Fumadocs.
- **Biome** lints and formats `.svelte` scripts and checks the file length of `.ts` files. It does not check the markup, and the unused-symbol rules are off for `.svelte` (see above). A markup problem is caught by the browser tests, not by Biome.

Biome's formatter moves the body of a `<script>` to column zero. Write it that way, as `bun run format` leaves it.
