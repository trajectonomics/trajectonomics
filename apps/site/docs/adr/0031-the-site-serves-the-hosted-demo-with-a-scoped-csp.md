# The Site serves the hosted Demo as static assets, with one scoped policy

The owner decided on 2026-11-23 to host the Demo Dashboard on the Site ([issue #342](https://github.com/trajectonomics/trajectonomics/issues/342), web [ADR 0009](../../../web/docs/adr/0009-the-demo-dashboard-is-hosted-on-the-site.md)). `apps/web` built the hosted target in [ADR 0028](../../../web/docs/adr/0028-the-hosted-demo-is-a-second-build-target-with-no-edit-client.md): `bun run build:hosted` writes `apps/web/dist-hosted/` with base path `/demo`. This record is the Site half: how that build reaches the assets root, how it is routed, and what it is allowed to load.

## Decision

- **The Site's build depends on the hosted build.** The `build` task in `apps/site/turbo.json` depends on `@trajectonomics/web#build:hosted`; `check` depends on it too, because the Site's check builds and scans its own output. `scripts/copy-demo.ts` runs as `postbuild` (and `postbuild:preview`) and copies all of `apps/web/dist-hosted/` to `dist/demo/`. Run directly rather than under turbo, it runs `bunx turbo run @trajectonomics/web#build:hosted` first, so `bun run check` inside `apps/site` never copies a stale or missing Demo. The copied files live under `dist/`, which the repository already ignores, so no Demo page or asset is committed.
- **The Demo is static assets, not a route.** `/demo/*` stays out of `run_worker_first` in `wrangler.jsonc`, so Workers Static Assets serves each file directly. The base path is fixed in the hosted build, and every page, link and `_app/` asset is under `/demo/`, so `html_handling: auto-trailing-slash` resolves `/demo/<route>/` to `<route>/index.html` and the Site's own `404-page` still answers a miss. No domain, route, Worker code or credential is added.
- **One policy, scoped to `/demo/*`.** `public/_headers` (copied to the assets root by Astro) is the Site's first headers file. It sets a `Content-Security-Policy` for `/demo/*` only: `default-src`, `img-src`, `font-src` and `style-src` name `'self'`; `connect-src` is `'self'`, which covers the Demo snapshot at `/demo/demo/snapshot.json` and `/demo/_app/version.json`; `form-action` is `'none'`, `base-uri` is `'self'` and `frame-ancestors` is `'none'`. The hosted build's prerendered body is an inline bootstrap script, so `script-src` also names `'unsafe-inline'`. The pages set inline `style` attributes but carry no inline `<style>` element (measured in the built `apps/web/dist-hosted/` output), so `style-src-attr` is exactly `'unsafe-inline'` and `style-src` stays `'self'` only; no other source, origin, scheme or keyword is allowed. The Site's own pages keep no policy, because the router injects an inline style and script ([ADR 0002](./0002-site-worker-with-static-assets.md)).
- **The Site's rules judge its pages; the Demo's rules judge the Demo.** `checkBuild` gives the Site's page and asset rules the files outside `demo/`, because the Demo is a different build with its own vocabulary and page weight. A Demo rule judges the files under `demo/`: the home exists, every page's links stay under `/demo/` (relative and root-relative alike, resolved against the page it is served at), and `_headers` sets the scoped policy with the directives above. The policy rule still fails a Content-Security-Policy anywhere else, in HTML or in a headers block for another path.
- **The way in is under the hero's window.** The hero draws a picture of the app; the "Try the demo" link under it goes to `/demo/`, in both Languages, as a quiet meta link in the install row's style. The built-file check requires the link on every Language home.

## Considered Options

- **Put the policy in the Worker.** Rejected: `/demo/*` is served by the assets binding, and Cloudflare does not apply `_headers` to responses the Worker generates; adding `/demo/*` to `run_worker_first` to attach the header would give up the static-assets route the issue asks for.
- **Allow only `'self'` for scripts and inline style.** Rejected: the hosted build's pages bootstrap from an inline script, so `script-src 'self'` would leave the Demo blank, and its `display: contents` wrapper is an inline style attribute, so `style-src-attr` without `'unsafe-inline'` would drop the wrapper (measured in the built output: no page carries an inline `<style>` element, so `style-src` itself can stay `'self'` only). Hashes of the inline scripts would be tighter, but the SvelteKit bootstrap carries a per-build version stamp, so a committed headers file could not hold them; that would need the headers file to be generated on every build.
- **Copy the Demo into `public/`.** Rejected: the copy would be tracked, and Astro would process the files as site content rather than leave the built output whole.
- **Link the Demo from the closing CTA.** Rejected: [ADR 0015](./0015-the-window-prints-a-prompt-and-no-command.md) keeps the CTA to its Copy control and its CLI way out, and the demo window is where a visitor has just seen the product.

## Consequences

- A broken hosted build fails the Site's build, so the Site never deploys a link to a Demo it did not copy.
- The bundle's validation library probes `Function("")` and falls back to its plain path when the policy blocks it, so every Demo page reports one blocked `eval` and works. The policy does not allow `'unsafe-eval'` to silence it; `e2e/demo-csp.e2e.ts` tolerates that one report and no other.
- The policy allows any inline script on a `/demo/` page, not only the build's own. Tightening it to hashes means generating `_headers` from the built pages, which this change does not do.
- A new Demo page or asset is covered by the link rule and the headers rule without a Site change. A new top-level Site directory that is not a page still passes through the Site's own rules as before.
