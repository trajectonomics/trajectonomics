# A tax result names the figures it used whose source is not yet confirmed

The owner's ruling on issue #52 is that `traj`'s tax output names, as assumptions, every figure it used whose source is not yet confirmed, until it is sourced. The tax core already records that status for every figure: `references/th/SOURCES.md` gives each `TH_2026_PARAMETERS` path a result of `match`, `derived`, `reported` or `unsourced`. Before this change nothing in a result said so, so a Projection stated a tax built on the Raidaai retirement ceilings, the Revenue Department's 2017 overview rates and a 15 per cent digital asset rate with the same confidence as the 60,000 baht personal allowance.

A result that carries Thai tax now carries an `assumptions` array. Each entry is `{ path, value, status, note }`: the figure's parameter path, the value the computation used, `reported` or `unsourced`, and one short sentence. `scenario tax` returns it at the top level, as the figures its stored Levy would use for the labels the Scenario's Flows carry; `projection run`, `fi` and each side of `projection compare` return it on every `taxYears` row, because a year uses a figure only when that year tallied something that needs it (a government pension fund rate only in a year with a government pension fund contribution). A computation that used no unconfirmed figure returns `[]`; `scenario tax --none` wrote no Levy, so it returns no field. The field is additive: no existing field changes name, order or type, and no tax figure moves. `traj schema` publishes it on all four commands, from the same definition that validates the result (ADR-0010).

The list is not computed here. `@trajectonomics/core/tax` holds a typed record of the unconfirmed figures, with the things a computation does that make it rely on each one, and a test compares the record with `SOURCES.md` in both directions: a row that becomes `match` fails the test until its entry is removed, and a new `reported` row fails it until an entry is added. The CLI asks the core which figures a Levy period used, from the Levy's own measures and what the period's tallies came to, and formats the answer. It holds no path, rate or status.

A Levy freezes the profile's fixed allowances into one const, so the period report cannot say which classes were stated (ADR-0036). The emitter therefore adds one audit const per stated allowance class whose ceiling or multiplier is unconfirmed, named `claim.<class>`. No Measure reads them, so every tax figure is unchanged and a Levy with no such allowance is byte-for-byte what it was. A tally's label says whether a retirement contribution was funded, and whether a rental or profession took the standard rate or the digital asset final withholding is read from whether the tally feeds a `scale` Measure, so an actual-expense election does not name a standard rate it did not use.

The human Format prints one `Assumptions` block after the result, one line per figure, each figure once even when several tax years use it, and nothing when the list is empty. The generic renderer leaves the nested arrays out so the block is the only place they print.

## Considered options

Storing the status in the CLI was rejected: a second list of figures would drift from `SOURCES.md` the moment a figure is sourced. Reading `SOURCES.md` at run time was rejected: the core is pure and its published bundle carries no document. A note in the existing `notes` array was rejected: notes are sentences a person must read, not a record a consumer can filter, and an agent would have to parse prose to learn the path. One top-level list for a Projection was rejected because a year that used no unconfirmed figure would then look the same as one that did. Recovering the stated allowance classes by decomposing the fixed const in the CLI was rejected: it would put the core's family and insurance rules in this repository.

## Consequences

Three result schemas grow a required `assumptions` array per tax year, `scenario tax` grows an optional one, and the committed projection golden is re-baselined once. When the tax core sources a figure, its row in `SOURCES.md` becomes `match`, the core's test names the entry to remove, and the figure leaves every result without a CLI change. The docs portal follows the release, not this pull request.
