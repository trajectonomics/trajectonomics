AI agent เก่งในส่วนของแผนการเงินที่ต้องใช้วิจารณญาณ มันถามว่าคุณมีรายได้เท่าไหร่ สังเกตสิ่งที่คุณลืม และอธิบายผลลัพธ์ด้วยภาษาที่คุณคุ้นเคย แต่มันไม่ได้เก่งเรื่องการเป็นเครื่องคิดเลข โมเดลภาษาเขียนคำตอบด้วยการ sampling ดังนั้น agent ตัวเดิมเมื่อถูกถามคำถามเรื่องเงินเดิมสองครั้ง ก็อาจให้ตัวเลขต่างกันได้

## agent ใช้วิจารณญาณ, traj คำนวณ

traj แบ่งงานออกเป็นสองส่วน agent ของคุณทำหน้าที่ใช้วิจารณญาณ: ถามข้อเท็จจริงจากคุณ ตัดสินใจว่าจะรันคำสั่งไหน แล้วอ่านผลลัพธ์กลับมาเล่าให้ฟัง ส่วนการคิดเลขทั้งหมดเกิดขึ้นใน `traj` ซึ่งเป็น command line ที่[ไม่เคยเรียกใช้โมเดลเลย](https://github.com/trajectonomics/trajectonomics/blob/main/apps/cli/docs/adr/0001-agent-first-no-llm.md) ดังนั้นตัวเลขทุกตัวที่ agent ยกมาบอกคุณ คือค่าที่ `traj` คืนกลับมา และ `traj` จะคืนค่าเดิมเสมอทุกครั้งที่คุณถาม

## อะไรที่ทำให้คำตอบเหมือนเดิม

การไม่เรียกใช้โมเดลเป็นแค่จุดเริ่มต้น โปรแกรมยังคลาดเคลื่อนได้ในจุดเล็ก ๆ น้อย ๆ ที่มองไม่ค่อยเห็น ดังนั้น `traj` จึงปิดทุกจุดเหล่านั้น:

- **ไม่ใช้ floating point กับเรื่องเงิน:** จำนวนเงินทุกยอดเก็บเป็นจำนวนเต็มของหน่วยที่เล็กที่สุด เช่น สตางค์สำหรับเงินบาท `1.005` บาทจะกลายเป็น 101 สตางค์ ไม่ใช่ 100 แบบที่การปัดเศษของ floating-point ให้ผล อย่างที่ [money package](https://github.com/trajectonomics/trajectonomics/blob/main/packages/core/money/README.md) เขียนไว้ว่า เศษคลาดเคลื่อนจาก float จะไม่มีวันเป็นตัวตัดสิน
- **คำนวณดอกเบี้ยทบต้นด้วยจำนวนเต็มแบบตรงเป๊ะ:** การทบต้นใช้เลขคณิตจำนวนเต็มทั้งหมด ตอนที่เราเทียบ JavaScript engine สองตัว พบว่า `Math.pow`, `exp` และ `log` ในตัวของทั้งสองเจ้าให้ผลต่างกันถึง 228 จาก 10,296 กรณี ดังนั้น projection engine จึง[ไม่ใช้ฟังก์ชันเหล่านั้นเลย](https://github.com/trajectonomics/trajectonomics/blob/main/packages/core/sim/docs/adr/0001-exact-integer-compounding.md)
- **ไม่พึ่งนาฬิกาของระบบ:** ทุกวันที่ที่คำสั่งใช้ทำงานต้องเป็นวันที่ที่คุณส่งเข้าไปเอง "วันนี้" คือวันที่คุณระบุ ดังนั้นคำสั่งที่คุณรันในวันพรุ่งนี้จะตอบคำถามเดิมเหมือนที่ตอบในวันนี้ ([ADR 0018](https://github.com/trajectonomics/trajectonomics/blob/main/apps/cli/docs/adr/0018-no-clock-in-ledger-commands.md), [ADR 0029](https://github.com/trajectonomics/trajectonomics/blob/main/apps/cli/docs/adr/0029-reads-take-their-date-from-the-caller.md))
- **output รูปแบบเดียวเสมอ:** agent ของคุณขอข้อมูลเป็น JSON ในทุกการเรียก และรูปแบบผลลัพธ์จะไม่มีการเดาจาก terminal ดังนั้นผลลัพธ์ที่ส่งผ่าน pipe กับที่แสดงบนหน้าจอจึงไม่มีวันไม่ตรงกัน ([ADR 0010](https://github.com/trajectonomics/trajectonomics/blob/main/apps/cli/docs/adr/0010-output-contract.md))

## ลองตรวจด้วยตัวเอง

ลองดูตัวอย่างการคำนวณล่วงหน้า 30 ปี เงินเดือน 40,000 THB ต่อเดือนที่โตตามเงินเฟ้อ 3% และเก็บออมทั้งหมดเข้าบัญชีเงินสดหนึ่งบัญชีที่ให้ผลตอบแทน 4.5% ต่อปี นับตั้งแต่วันที่ 31 มีนาคม 2026 โดยไม่ได้หักภาษี ตัวเลขจึงเป็นยอดก่อนภาษี

บันทึกไฟล์นี้ชื่อ `base.json` ยอดเงินมีหน่วยเป็นสตางค์ และอัตราต่าง ๆ มีหน่วยเป็น basis points:

```json
{
  "schemaVersion": 4,
  "currency": "THB",
  "economy": { "inflation": 300 },
  "accounts": [{ "id": "cash", "kind": "asset", "rate": 450 }],
  "flows": [
    {
      "id": "salary",
      "kind": "income",
      "earned": true,
      "amount": 4000000,
      "frequency": "monthly",
      "start": "2026-01-01",
      "growth": "inflation"
    }
  ],
  "cashflow": {
    "surplus": [{ "account": "cash" }],
    "contribute": [],
    "withdraw": []
  }
}
```

จากนั้นลองรันใน ledger ชั่วคราวเพื่อไม่ให้กระทบข้อมูลจริงของคุณ ขั้นตอนนี้ต้องมี `traj` 0.4.0 และ `jq` สำหรับ macOS ให้ใช้ `shasum -a 256` แทน `sha256sum`:

```sh
export TRAJ_HOME="$(mktemp -d)"
traj init
traj scenario apply base --file base.json
traj projection run --scenario base \
  --as-of 2026-03-31 --horizon 2056-03-30 --json \
  | jq -c .tables | sha256sum
```

เราลองรันด้วย `traj` 0.4.0 ไปห้ารอบ และรันซ้ำอีกครั้งใน ledger ใหม่อีกชุด ทุกรอบพิมพ์ hash เดียวกันออกมา:

```text
dd9bc2f0dd33caed788ad28b92742748ed95c3f683e332af577a6f466fb807ad
```

ทุกรอบยังได้มูลค่าสุทธิ ณ วันปิดรอบ 30 มีนาคม 2056 เท่ากันคือ 43,504,723.86 THB หรือ 17,924,821.75 THB ในมูลค่าจริงหลังหักเงินเฟ้อ 3% ตามแผน ลองรันบนเครื่องของคุณดู คุณควรได้ hash เดียวกันนี้จนถึงสตางค์สุดท้าย ถ้าไม่ตรง แปลว่าเป็น bug และเราอยากให้แจ้งให้เรารู้

## deterministic ไม่ได้แปลว่าอะไร

ความแน่นอนซ้ำได้ (deterministic) ไม่ใช่สิ่งเดียวกับความถูกต้อง `traj` คำนวณตามสิ่งที่แผนของคุณระบุไว้อย่างตรงไปตรงมา ถ้าสมมติฐานผิด เช่น อัตราผลตอบแทน 4.5% ที่คุณไม่มีทางได้จริง คำตอบที่ได้ก็จะผิดแบบเดิมเป๊ะทุกครั้ง นั่นคือเหตุผลที่ต้องเก็บการใช้วิจารณญาณไว้กับคุณและ agent แล้วปล่อยให้การคิดเลขอยู่ในเครื่องมือที่คุณตรวจสอบการทำงานได้

วันนี้ `traj` รองรับเงินบาทไทยแล้ว ใช้งานฟรี เป็น open source และเก็บ ledger ของคุณไว้บนเครื่องของคุณเอง

## ลองใช้ดู

ติดตั้ง `traj` แล้วส่ง setup skill ให้ agent ของคุณ ดูคำสั่งทั้งหมดได้ที่[หน้าติดตั้ง](/docs/cli/installation/) จากนั้นลองถามคำถามเรื่องเงินกับ agent ของคุณสองครั้ง แล้วเทียบคำตอบกันดู
