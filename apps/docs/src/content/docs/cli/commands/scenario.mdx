`traj scenario` manages Scenarios, the named what-ifs. A Scenario is a JSON document, and an
override changes one value in it by a dotted path with stable ids, such as `flows.salary.amount`.
`traj scenario apply --template` prints a document to start from. A Scenario can also carry a tax
Levy, a household, notes and a main-plan mark, each beside its document.

## `traj scenario apply <name>`

Create or update a Scenario from a JSON document, save a what-if as the plan, or print a template.

- `--file <string>` — the JSON document's path, or `-` for stdin; required unless `--template`
- `--template` — print a complete document to start from and open no Data directory; with `--as-of`
  pre-fill it from the Baseline at that date, and with a name and `--as-of` save it instead
- `--as-of <string>` — with `--template`, the date the document is pre-filled at, as `YYYY-MM-DD`
- `--from-history` — with `--template --as-of`, one income or expense Flow per row of
  `traj baseline rates`, in place of the two zero Flows
- `--months <number>` — with `--from-history`, the window length, 3 to 36; default 12
- `--dry-run` — report the row and roll the write back
- `--decimal` — read a document whose money amounts are decimal strings of the major unit, such as
  `"350.00"`, not integer minor units
- `--if-hash <string>` — refuse the write unless the stored plan's `contentHash` is this one
- `--set <string>` — replace one existing dotted document path with a JSON value; repeatable
- `--without <string>` — take one list item out by its id before any `--set`; repeatable
- `--add <string>` — add one new list item as `list=<json>`, after any `--without` and before any
  `--set`; repeatable

There are three forms.

**The document form** (`--file`) stores a complete document. It replaces the whole document, leaves
the household, notes and main mark as they were, and drops an Owner or an anchor whose item the new
document no longer holds, listing it in `droppedAnchors` or `droppedOwners`.

**The template form** (`--template`) prints a document. Without `--as-of` it is the minimal document
below. With `--as-of` it names your ledger's Accounts by id and sets each Flow to start on that
date, so the document starts from what you hold that day. `--from-history` replaces the two zero
Flows with one income or expense Flow per Account `traj baseline rates` carries, using the Account's
id as the Flow id and its run-rate as the amount. `--decimal` prints the same document in decimal
form. A name with `--template --as-of` saves the pre-filled template as a new plan and marks the
values `traj` wrote as assumed; a name without `--as-of` is refused.

**The what-if form** (`--set`, `--without` or `--add`, with no `--file`) reads the stored plan,
applies the same Overrides `projection run` applies, and stores the result. A what-if that projects
is the one that is saved, and an apply that leaves the plan unchanged writes nothing. A `--set` may
begin the estate block, an asset Account's `volatility`, a Flow's or Milestone's `displayLabel`, an
income or contribution Flow's `label`, a surplus step's `share` and `upTo`, `economy.inflationVolatility`,
and a withdraw entry's `downTo`. Items of `cashflow.surplus` and `cashflow.withdraw` are addressed by
position from 0, such as `cashflow.withdraw.0.downTo`. `--add` takes `accounts`, `flows` or
`milestones`, and the item carries its own `id`.

`--if-hash` makes a write conditional on the plan you read: when the stored `contentHash` is not the
one named, the write is refused with `scenario_changed` at exit code `5` and nothing is written. The
household is not in `contentHash`, so a household write uses `householdHash` instead.

The template documents name your own Account ids, so they are shown as commands rather than checked
examples.

```bash
traj scenario apply --template > base.json           # Print the document to start from.
traj scenario apply --template --as-of 2026-03-31    # Print a Scenario pre-filled from the Baseline at one date, to edit and apply.
traj scenario apply base --template --as-of 2026-03-31  # Save the pre-filled template under a new name.
traj scenario apply income --template --from-history --as-of 2026-03-31  # Print a template whose Flows are what the Ledger ran at.
traj scenario apply base --file base.json            # Create a Scenario, or update it when the document changed.
traj scenario apply base --file - < base.json        # Read the document from stdin.
traj scenario apply base --file base.json --if-hash jcs1:sha256:...  # Write only if the plan still holds that hash.
traj scenario apply base --set flows.salary.amount=9000000 --dry-run  # Save one changed assumption, and roll it back.
traj scenario apply base --set 'flows.salary.amount="90000.50"' --decimal --dry-run  # The same change as a decimal amount of THB.
traj scenario apply base --without flows.gym --dry-run  # Save the plan with one Flow taken out.
traj scenario apply base --add 'flows={"id":"extra","kind":"expense","amount":"1000.00","frequency":"monthly","start":"2026-04-01","growth":{"bps":0}}' --decimal --dry-run  # Save the plan with one new Flow.
```

apply it. The latest release prints:

`traj schema scenario apply` names the document version the installed CLI accepts, so print the
template rather than copying this one into a newer CLI.

Amounts are integer minor units (cents or satang, depending on the currency), rates and inflation
are integer basis points, and dates are `YYYY-MM-DD`. `growth` is `"inflation"` or
`{ "bps": <integer> }`. `cashflow.surplus` is the order surplus fills Accounts,
`cashflow.contribute` is the funding priority for contributions, and `cashflow.withdraw` is the
withdrawal order.

```bash exec
traj scenario apply base --template --as-of 2026-03-31 --json | jq -r .status
```


```bash exec
traj scenario show base --json | jq '{name: .scenario.name, taxed: .scenario.taxed, notes: .scenario.notes, main: .scenario.main, assumed: [.scenario.assumed[].kind]}'
```

## `traj scenario diff <a> <b>`

Compare two Scenario documents path by path.

```bash
traj scenario diff base early  # Show what a what-if changed.
traj scenario diff base base   # Compare a Scenario with itself.
```

## `traj scenario fork <from> <name>`

Copy a Scenario under a new name. The copy keeps the source's notes unless `--no-notes` is given,
and treats its own `--set` paths as stated values.

- `--set <string>` — replace one existing dotted document path with a JSON value; repeatable
- `--without <string>` — take one list item out by its id before any `--set`; repeatable
- `--add <string>` — add one new list item as `list=<json>` after any `--without` and before any
  `--set`; repeatable
- `--decimal` — read each money amount of a `--set` or `--add` item as a decimal string of the major
  unit instead of satang
- `--no-notes` — leave the source's notes behind; by default the copy keeps them
- `--dry-run` — report the row and roll the write back

```bash
traj scenario fork base early                                  # Copy a Scenario under a new name.
traj scenario fork base fresh --no-notes                       # Copy it without the notes kept on the source.
traj scenario fork base raise --set flows.salary.amount=9000000  # Copy it with one assumption changed.
```

## `traj scenario household <scenario>`

Set the people whose ages pin a Scenario's dates and who owns its items, or remove them.

- `--file <string>` — the household JSON document's path, or `-` for stdin
- `--none` — remove the household; the dates it anchored stay as they are
- `--dry-run` — report the row and roll the write back
- `--if-hash <string>` — refuse the write unless the stored `householdHash` is this one

The document names one holder, at most one partner who may join later, and any dependents, each with
a birth month and a life expectancy. Its `anchors` pin a date field of the plan to a person's age, to
life's end or to a partner's join, and a version 2 document's `owners` names the person who owns an
item, or `shared` for both. The command writes the anchored dates into the Scenario
document when the household is saved; a document `scenario apply` receives must state the same dates,
and a different one is refused at its path.

```bash
traj scenario household base --file household.json           # Set the people, their anchors and owners.
traj scenario household base --file household.json --dry-run # Show the dates the household would write.
traj scenario household base --none                          # Remove the household; the anchored dates stay.
```

## `traj scenario list`

List the live Scenarios by name, with `taxed`, `hasNotes`, `hasMilestones` and `main` on each row.

```bash
traj scenario list --json  # Show the Scenarios as JSON.
```

## `traj scenario main [scenario]`

Mark a Scenario as the main plan, or take the mark off.

- `--clear` — take the main-plan mark off instead of setting it
- `--dry-run` — report the change and roll the write back

At most one live Scenario holds the mark; marking another moves it in one write and names the plan it
left in `previous`. The mark is a label for people, agents and the Dashboard, not a default: every
read still needs `--scenario`. A fork is never the main plan, and a Scenario applied under a new name
is not either.

```bash
traj scenario main base            # Mark base as the main plan.
traj scenario main base --dry-run  # Show which plan would become the main plan, and roll it back.
traj scenario main --clear         # Take the main-plan mark off.
```

## `traj scenario notes <scenario>`

Keep plain-text notes on a Scenario, or clear them.

- `--text <string>` — the notes: plain UTF-8, at most 10,000 characters, with no control character
  but a newline and a tab
- `--file <string>` — read the notes from this path, or `-` for stdin
- `--clear` — remove the notes
- `--dry-run` — report the row and roll the write back

Notes stay outside the Scenario document, so writing them changes no byte of it and no
`contentHash`. A leading byte order mark is dropped and a Windows line ending is read as a newline;
notes that are empty are refused, so `--clear` is the one way to say none.

```bash
traj scenario notes early --text "Retire at 55, sell the condo in 2031."  # Write down what the plan assumes.
traj scenario notes early --file notes.txt                                # Keep the text of a file as the notes.
traj scenario notes early --clear                                         # Take the notes off.
```

## `traj scenario rename <scenario> <name>`

Give a Scenario another name; its id, document and hashes stay.

- `--dry-run` — report the row and roll the write back
- `--if-hash <string>` — refuse the write unless the stored `contentHash` is this one

A name a live plan already holds is refused as `scenario_name_taken`, and a rename to the name it
already has is already true: it exits `0` with `status: "unchanged"` and writes nothing.

```bash
traj scenario rename early retire-at-55            # Give the Scenario a name that says what it assumes.
traj scenario rename early retire-at-55 --dry-run  # Show the row the rename would write, and roll it back.
```

## `traj scenario rm <scenario>`

Tombstone a Scenario and free its name.

- `--force` — remove the main plan too, which takes the main-plan mark off
- `--dry-run` — report the row and roll the write back

Removing the main plan is refused as `scenario_is_main` at exit code `5`, and the hint names
`traj scenario main` to choose another or `--clear`. `--force` removes it anyway and reports
`mainCleared: true`.

```bash
traj scenario rm early            # Retire a Scenario by name.
traj scenario rm base --force     # Remove the main plan anyway.
traj scenario rm early --dry-run  # Show what rm would do.
```

## `traj scenario show <scenario>`

Show one Scenario with its document, household and owners.

- `--decimal` — print money as decimal strings of the major unit, ready to edit and apply with
  `--decimal`

The `scenario` it prints carries `id`, `name`, `contentHash`, `forkedFrom`, `version`, its timestamps
and the `document`; beside it are `household` (or `null`), `householdHash`, `tax` (the stored tax
profile, or `null`), `taxed`, `taxAllowances` (`stated` and `notStated`, only on a taxed plan that
keeps a profile), `notes` (or `null`), `main`, and `assumed`.

`assumed` is always printed, and `[]` when the plan assumes nothing. Its four kinds are a
`template-default` value `traj` wrote that no edit has touched, an `unlabelled-income` Flow in a taxed
plan, an `unstated-allowance` class, and a `tax-figure` whose source is not yet confirmed. Each item
carries a `path` and, where a command states it, a `hint`. The human form prints the list as a
`This plan assumes (values nobody stated):` block after the Scenario.

```bash
traj scenario show base                                 # Show a Scenario by name.
traj scenario show base --json | jq .scenario.document  # Print only the document.
traj scenario show base --decimal                       # Print the document with money in major units.
```

## `traj scenario tax <scenario>`

Write or remove the tax Levy a Scenario's labelled Flows are taxed under. A Levy tallies labels and
never guesses them, so `--label` says which Section 40 class each income Flow belongs to.

- `--tax <string>` — write the Levy for this jurisdiction: `th-2026`, Thailand's 2026 income tax
- `--filing-status <string>` — the taxpayer's filing status; needs `--tax`, defaults to `single`
- `--children <string>` — children counted for the child allowance; needs `--tax`, defaults to 0
- `--children-at-higher-rate <string>` — children born 2018 or later, allowed at the higher rate; a
  subset of `--children`, needs `--tax`
- `--parents <string>` — parents aged 60 or over with income of at most 30,000 THB whom the taxpayer
  supports; needs `--tax`
- `--disabled-care <string>` — relatives with a disability the taxpayer cares for; needs `--tax`
- `--social-security <string>` — social security contributions paid in the tax year, in THB; needs
  `--tax`
- `--life-insurance <string>` — life insurance premiums paid in the tax year, in THB; needs `--tax`
- `--health-insurance <string>` — the taxpayer's own health insurance premiums, in THB; needs `--tax`
- `--parent-health-insurance <string>` — health insurance premiums paid for the taxpayer's parents,
  in THB; needs `--tax`
- `--spouse-life-insurance <string>` — life insurance premiums paid for a spouse with no income, in
  THB; needs `--tax` and a filing status that allows the spouse allowance
- `--mortgage-interest <string>` — home-loan interest paid in the tax year, in THB; needs `--tax`
- `--donation2x <string>` — donations that the statute counts twice, such as education and
  hospitals, in THB; needs `--tax`
- `--donation1x <string>` — donations counted once, in THB; needs `--tax`
- `--label <string>` — classify one Flow for tax as `<flow>=<label>`, such as
  `salary=income.section40_1`; repeatable, needs `--tax`
- `--merge` — change only the profile flags given and keep the rest of the stored tax profile
- `--from-stored` — write the Levy again from the stored tax profile, for example after a tax-year
  update
- `--none` — remove the tax Levy and the stored tax profile instead of writing one
- `--dry-run` — report the row and roll the write back
- `--if-hash <string>` — refuse the write unless the stored `contentHash` is this one

The filing statuses are `single`, `married_no_income_spouse`, `married_separate`, `married_joint` and
`married_separate_40_1_joint_rest`. The deduction flags state what the taxpayer paid; the statutory
ceilings are applied by the tax core, not by the command. `traj help scenario tax` lists every
accepted `--label` value.

The write keeps the profile it was given beside the Scenario, as `tax` on
[`scenario show`](#traj-scenario-show-scenario). `--merge` lays the flags it carries over that
profile and keeps every other item, so `--merge --children 2` changes only the children;
`--from-stored` writes the Levy again from the profile and takes no profile flag. Both refuse a plan
with no stored profile, and a write of the whole profile states it again. `--none` removes the Levy,
the labels and the profile together.

With `--filing-status married_joint` and a household that has a partner and owners, the Levy is one
over both people as Filers: state each label bare, and the CLI adds the Owner's suffix
(`income.section40_1@me`, or `@shared` for income of both). With `married_separate` the CLI writes
one Levy per person who has income, and each allowance flag takes an optional person
(`--parents partner=2`); a bare value names the holder, and each Return's children default to 0.
State the interest on one loan borrowed together as `--mortgage-interest shared=<amount>`, which
the two Returns split in the year both have income.

A result that uses Thai tax carries an `assumptions` array: one entry per tax figure the
computation used whose source is not yet confirmed, with its `path`, its `value`, its `status`
(`reported` or `unsourced`) and one sentence of `note`. A figure that is later sourced leaves the
list without a change to the command. The human form prints the same entries as an `Assumptions`
block after the result.

```bash
traj scenario tax base --tax th-2026 --label salary=income.section40_1                                                                                                                                     # Charge Thailand's 2026 income tax on the salary this Scenario declares.
traj scenario tax base --tax th-2026 --filing-status married_joint --children 1 --label salary=income.section40_1                                                                                          # The same Levy under a married-joint profile with one child.
traj scenario tax base --tax th-2026 --filing-status married_no_income_spouse --life-insurance 20000 --mortgage-interest 30000 --social-security 9000 --donation1x 5000 --label salary=income.section40_1  # The same Levy with the deductions a Thai employee usually has.
traj scenario tax base --merge --children 2                                                                                                                                                                # Change the children counted and keep every other item of the profile.
traj scenario tax base --from-stored                                                                                                                                                                       # Write the Levy again from the stored profile.
traj scenario tax base --none                                                                                                                                                                              # Take the tax Levy and its profile out, so the figures are pre-tax again.
```
