---
title: telemetry
description: Show or change anonymous usage counting.
---

`traj` counts its own use, so the project can see how many people run it each week. Apart from the
npm launcher's one-time download of the binary, that count is the only thing `traj` sends over the
network. Your ledger, Scenarios and Projections never leave the machine. `traj telemetry` shows whether counting is on and why, and turns it off or back on.

## `traj telemetry status`

Show whether counting is on, the reason, and the file that holds the choice. `--json` prints the same
three facts as JSON.

```bash
traj telemetry status  # Show the current choice and why.
```

The output depends on the machine it runs on, so it is not a checked example. It prints three facts:
`enabled`, the `reason` (for example `do_not_track` when the `DO_NOT_TRACK` variable is set), and the
path of the state file.

## `traj telemetry off`

Stop counting on this machine, and delete the random id it sent.

```bash
traj telemetry off  # Stop counting on this machine.
```

## `traj telemetry on`

Count again, after `off`. It does not override the environment: see below.

```bash
traj telemetry on  # Count again.
```

## What one event holds

After a command finishes, a detached process sends one anonymous event to PostHog (EU), so the
command never waits for the network. The event holds:

- `command` — the command name, such as `tx add`, or nothing when the command line named none
- `exit_code` and `error_code` — how the run ended, such as `invalid_input`
- `format` — `human` or `json`
- `version`, `os` and `arch` — the CLI version and the platform

It never holds your ledger, arguments, flag values, account names, amounts, file paths, the data
directory or any environment variable. As with any web request, PostHog sees the IP address the
request comes from.

## Where the random id lives

Events from one machine are grouped by a random id, created on the first send. It is stored in
`telemetry.json` in `$XDG_CONFIG_HOME/traj`, or `~/.config/traj` when that variable is not set; on
Windows it is in `%APPDATA%\traj`. That directory is outside the data directory, so
[`traj data remove`](/cli/commands/data/) does not delete it. `traj telemetry off` deletes it. A
machine where that file cannot be written sends nothing, because an id that is not kept would count
as a new person on every run.

## Two ways to stop it

- `traj telemetry off`, which stores the choice for this machine
- `DO_NOT_TRACK=1` in the environment of the command

`traj telemetry on` does not override the environment: a `DO_NOT_TRACK` or `CI` setting still stops
counting, and `status` says which one does.

CI runners, where `CI` is set, and development builds never send.

## The first-run notice

The first successful command that counts prints one line on stderr saying that usage is counted and
how to stop it. It prints that line once. An error never prints it, because an error keeps stderr
for its own message.

See [Configuration](/cli/configuration/) for the environment variables, and [Commands](/cli/commands/)
for the global options, exit codes and error envelope.
