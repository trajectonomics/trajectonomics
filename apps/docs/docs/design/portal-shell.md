# Design brief: Docs Portal shell

The brief behind [ADR 0004](../adr/0004-docs-portal-shell.md). Language is in [`GLOSSARY.md`](../../GLOSSARY.md).

## Reference and traits

Primary reference: Stripe Docs. Three traits to copy, with no pixel matching:

1. The audience split lives in persistent navigation, and the front door is one calm page.
2. A readable column with generous vertical rhythm. Fumadocs' 900px page column is the measure.
3. Restrained neutral chrome where code blocks and one accent colour carry emphasis.

Hierarchy reference: twenty.com (owner, 14 Nov 2026), for the docs pages and the Landing Page: a quiet header, one large tight-tracked headline, hairline borders, generous space. No product imagery and no palette of its own — the colours are the design-system Themes. The Landing Page's sections are its own (see [Landing Page](#landing-page)).

## Shell

| Part | Decision |
| --- | --- |
| Layout | Fumadocs notebook layout with a desktop header and the sidebar. |
| Tabs | In the one header row, centred (lg and up), in the sidebar Tab dropdown below lg. The current Tab is marked `aria-current="page"` ([ADR 0009](../adr/0009-shell-spans-the-page-one-header-row-and-twentys-sidebar.md)). |
| Width | The Landing Page is capped at 1400px. The docs pages span the page: the sidebar sits at the left edge, the table of contents at the right, and the reading column keeps Fumadocs' 900px measure, centred between them ([ADR 0009](../adr/0009-shell-spans-the-page-one-header-row-and-twentys-sidebar.md)). |
| Table of contents | Absent on pages without headings. |
| Look | The brand's light/dark Themes (`@trajectonomics/brand/current/{light,dark}.css`), mapped onto the shell's variables by the theme seam and selected by `data-theme` on `<html>`. The Theme is forced to `dark` for every reader while the organisation ships one look ([docs#89](https://github.com/trajectonomics/docs/issues/89); the owner reversed the earlier light-only decision on 17 November 2026): the theme provider's forced value wins over the stored preference and the device's scheme, and the toggle is off. The light Theme CSS stays loaded and mapped, so light's return is that one value plus the switch; the seam declares `color-scheme: dark` so a reader with JavaScript off gets the dark rendering mode too. Contract v2 radius, font-family and font-size roles drive the Tailwind variables the shell consumes, and the spacing scale's base unit drives `--spacing` (design-system#60); the radius roles are declared once for every layout and capped at the card role, so no surface is rounder than a Site card — the Site's shape ([site ADR 0007](https://github.com/trajectonomics/trajectonomics/blob/main/apps/site/docs/adr/0007-landing-page-restyle-twenty-language.md), docs#90). Inter Variable ships from the assets package's font stylesheet (design-system#61). The shell draws no shadow: hover reads as the secondary surface, keyboard focus is a 2 px ring on the ring role, and Fumadocs' floating panels take a hairline in place of a shadow. |
| Home link | The Site Home. Every page carries it as the header's glyph tile, as the blog does: the glyph on a tile at the left of the header, 32 px and 40 px from `sm` up, named "Trajectonomics home" (`/`, the Site Home on the same host, full document load, no prefetch, [ADR 0017](../adr/0017-the-portal-is-served-under-the-sites-host.md)), with a `Docs` marker in the display face beside it that links to the Landing Page ([ADR 0009](../adr/0009-shell-spans-the-page-one-header-row-and-twentys-sidebar.md)). It is in the header at every width, never behind a menu. The Landing Page also ends with its own row of three links, whose Site Home link (labelled `Site Home`, and root-relative like the tile) is a link in the page body ([docs#76](https://github.com/trajectonomics/docs/issues/76)). |
| Agent pointer | None a reader sees. Every page with a Markdown twin opens its `<body>` with one sentence for an Agent, "For AI agents: this page as Markdown · the Docs index", clipped to a pixel, hidden from the accessibility tree and out of the tab order, with the alternate Markdown link in the page head. It is no part of the shell: not in the sidebar's top block and not in a header. The Landing Page's visible `llms.txt` and `index.md` links and its prompt panel are page body for a reader handing the portal to an Agent, not this pointer ([ADR 0010](../adr/0010-the-portal-serves-markdown-by-request.md), [ADR 0009](../adr/0009-shell-spans-the-page-one-header-row-and-twentys-sidebar.md)). |

## Landing Page

The owner asked for a Landing Page that hands the portal to an Agent (21 November 2026). Two references: [twenty.com](https://twenty.com) for the hierarchy — one large tight-tracked headline, hairline cards, generous space — and [Cloudflare's developer docs](https://developers.cloudflare.com/) for the Agent hand-off — a "Copy prompt" control beside the hero, and the index, per-page Markdown and `Accept: text/markdown` named on the page. This replaces the earlier "nothing else in the page body" rule ([docs#76](https://github.com/trajectonomics/docs/issues/76)); the header is unchanged.

Top to bottom: a hero (release line, headline, the division of labour, one sentence, the Agent's two files) beside the prompt panel; **Read it yourself**, the audience entries with a picture each; **For Agents**, the one-source-to-three-channels picture; the ending. The owner's follow-up (27 November 2026) made the page visual-first: a picture carries the shape, and words drop to labels, a sentence, or a mono chip.

| Part | Decision |
| --- | --- |
| Headline | "Your Agent asks. traj computes." — the division of labour on the Agent page ([cli ADR 0001](https://github.com/trajectonomics/trajectonomics/blob/main/apps/cli/docs/adr/0001-agent-first-no-llm.md)), with the second line muted. The portal's name stays the document title and the header mark's name. |
| Hero picture | An `<ol>` named "How a question gets its answer": **You** asks "What's my net worth?", **Your Agent** runs `traj balance --as-of 2026-03-31`, and **traj** answers **879.50 THB** — the Quickstart's own net worth. Each node is a card, the result takes the accent border, and the arrows between nodes are `aria-hidden`. Horizontal from `xl` up; below `xl`, phones included, it stacks vertically with down arrows. One sentence under it: "traj never calls a model, so every number comes from the tool." The purpose sentence stays the page's meta description rather than page body. |
| Release line | A bordered pill above the headline, `Docs for traj <version>`, read at build time ([ADR 0002](../adr/0002-authored-content-with-proposal-only-sync.md)). `verify:build` fails a built Landing Page that does not state it. No other page carries a release line. |
| Prompt panel | A card with the heading "Start with your Agent", one sentence of lead, the page's one primary button, **Copy prompt** in the accent role, (it reads **Copied** for two seconds, or **Copy failed** when the browser has no clipboard or refuses, and announces either through a `status` region; the prompt stays selectable), and the prompt itself in a `<pre>`. The prompt's words live in `src/lib/agent-start.ts` and the page, the Markdown twin and the tests read them from there. It names no install command: it sends the Agent to the Installation page's twin and its "Add the agent skill" section, where the command is authored ([ADR 0010, the skill requirement](../adr/0010-the-portal-states-the-skill-requirement.md)). |
| Agents start at | Two visible mono chips under the picture, `llms.txt` and `index.md`, led by the muted label "Agents start at"; each chip is a full document load with no prefetch. They are page body, not shell: the hidden pointer at the top of `<body>` stays the first link to the Docs index ([ADR 0010](../adr/0010-the-portal-serves-markdown-by-request.md)). |
| Entries | One card per Tab, from its Tab definition, and each opens with a small `aria-hidden` picture: the Operator's terminal (`$ traj balance --as-of 2026-03-31`, then `879.50 THB`) and the Contributor's three steps, Report → Change → Check. Below it: the audience as a mono label, the Tab's `entry` as the card's one link, the `description` as its `aria-describedby` target, and the Tab title with an arrow. The link is stretched over the card. They stay the only links into a Tab, which `verify:build` checks. |
| For Agents | A source card, "Any docs page / as Markdown", branches on `lg` into three chips — the Docs index, any page as Markdown, ask for Markdown — each with its route label, a line of ten words at most and its snippet with an icon copy control named `Copy <title>`. The chips stack under the source on phones. The lines are text, not links, so the Tab-link rule above holds. |
| Ending | A hairline above one row of three links, resting at the bottom of the page body: **Site Home** (`/`, full document load, no prefetch), **Source** (this repository) and **License** (the AGPL-3.0-only license file). It is a block of links, not a `<footer>` element, because the home layout puts the page body inside `<main>` and a `footer` there exposes no `contentinfo` landmark. |
| Markdown twin | `/docs/index.md` carries the same order for an Agent: the prompt in a `text` fence under "Start with your Agent", the entries, then the three routes under "For Agents". |
| Orange | The brand's orange is the Theme's `accent` role (`#ea580c` in dark), the colour the shell uses for a hovered control; the page adds no colour of its own. It marks the action and the brand moments: the headline's second line, the **Copy prompt** button, the release dot, the prompt's caret and the hairline over the prompt panel, a hovered Agent chip's border, a hovered card's border and arrow, the hero result's border, and a copied route's check. Orange text sits only on the page ground, where it holds 4.9:1; small text on a card stays neutral, because orange on the card ground is 4.5:1 at best. The audience cards no longer fill with the accent on hover, which put muted text on orange. |
| Motion | `src/styles/motion.css`, movement and opacity only. Once on load: the hero rises in steps 90 ms apart, and the prompt fades in line by line. Looping: the prompt's caret blinks, the release dot pings, and an orange glow behind the prompt panel drifts over 14 s. On hover: a card lifts 4 px and its arrow slides. All of it sits behind `prefers-reduced-motion: no-preference` (`motion-safe:` in the markup), so a reader who asks for less motion gets the page at rest. The text is in the document from the first paint, so an Agent and a screen reader never wait for an animation. The browser tests' settled-page wait skips infinite loops, which never settle by design. |
| Shape | Hairlines, no shadow, nothing rounder than a card; the release pill, its dot, the glow and the step rail's number circles are round shapes, the circles cut with `clip-path: circle(50%)`. Colours are the Theme's roles only. The flow nodes and route chips are cards. |

### Pictures in docs pages

A docs page opens with its picture, from Markdown alone, so the Markdown twin stays plain (no JSX in an `.mdx` body). `src/lib/flow-fence.ts` turns a ```` ```flow ```` fence into a named ordered list (nodes separated by `->`, the last one the result), `src/lib/tree-fence.ts` turns a ```` ```tree ```` fence into nested lists with `aria-hidden` glyphs, `src/lib/link-cards.ts` turns a "What next" list into link cards, and `src/styles/prose-*.css` draws an ordered list as a numbered step rail. Every picture is real text: an arrow, glyph or connector is `aria-hidden`, and no `.mdx` file carries an element.


## Surface states

| State | Behaviour |
| --- | --- |
| Empty | No page is empty: the content skeleton (docs#38) gave every Tab page content. `verify:build` fails a built page that still shows "This page is a placeholder". |
| Loading | None for static pages; the search dialog keeps its Fumadocs states. |
| Error | A failed search-index fetch shows the dialog's empty result; no custom UI. |
| 404 | Our own body inside the shell, with search and a link to `/docs/`. |
| Mobile (390px) | Fumadocs' header menu, sidebar drawer and table-of-contents popover. |

## Assets

All from `@trajectonomics/brand/current/`: every page's header shows the Site's glyph tile — the package's `logo/mark.svg`, 32 px on a tile painted from the Theme's primary roles, naming itself "Trajectonomics Docs" — Layout.astro links the Favicon Set, and the global stylesheet imports the Inter Variable font stylesheet (`fonts/inter.css`). docs owns none. The social card is still pending (design-system#34).

## Checking a change

`bun run check` runs `verify:build` against the built site. Layout at 1280, 2000 and 390px and dark mode are checked by screenshots in the pull request until [docs#9](https://github.com/trajectonomics/docs/issues/9) decides a browser test strategy. A Surface ticket — a Spec that names a visual reference ([factory ADR 0017](https://github.com/trajectonomics/factory/blob/main/docs/adr/0017-surface-design-gate.md)) — also commits the rendered screenshots under `docs/screenshots/` — `bun run screenshots:curated` writes them — on the branch, at 1280, 2000 and 390 px in light and dark, and names the reference in the pull request body; its pull request merges only on the owner's approval review or explicit yes. The curated set covers every page at the three widths in both Themes, plus the copy control's hover state at 1280 px, the open search dialog at 1280 px (docs#90): they are the surfaces where a shadow becomes a hairline. It also shows the open sidebar drawer at 390 px, where a phone reaches the search and the Tab dropdown. The shell's geometry — the page-wide grid, the one header row, the sidebar's top block and the dark-only Theme — is also checked by `e2e/shell.e2e.ts` (docs#91). While the Theme is forced to dark, the set captured with a light device renders the same dark look: both sets stay committed, so light's return needs no new evidence.
